## Timeline 文字记录

Timeline 记录属于当前 OzID 账号，浏览器通过 BFF 的 `bff.timeline.v1.TimelineService` 访问。服务端从内部会话凭证取得用户身份，客户端不能提交用户 ID。

记录需要标题、日期和 IANA 时区，可选发生时间、分类、地点、备注、金额/三位大写币种和网页书签。日期与时间由服务端解析和排序；金额使用最小货币单位整数保存。网页书签只保存经过 scheme、控制字符、长度和内网目标校验的用户输入，不会请求目标 URL。

列表支持搜索、分类和日期范围组合筛选，并按发生时间倒序、ID 升序稳定排序。删除先进入回收站，恢复后回到原排序位置；v1 网页和 MCP 不提供永久删除入口。更新和删除可携带 expected revision，版本不匹配返回冲突；创建携带 mutation id 时重放返回原记录。

账号注销会删除 Timeline 记录，并把关联对象的 opaque key 放入不含用户 ID 的清理队列。清理队列可安全重试：附件删除与账号注销入队同一对象只会产生一行（`ON CONFLICT (object_key) DO NOTHING`），重复删除不会重置已完成或已计数的清理状态；服务运行时每分钟排空一次队列，对象存储暂时失败的条目保留为 pending 并累计 `attempts`，下一轮重试，成功后标记 done，不影响其他条目。BFF 未配置 Timeline upstream 时不会挂载入口。数据库拓扑（与 Tripmap 同库）和升级步骤见 [Timeline 与 Tripmap 共享迁移](../backend.md#timeline-与-tripmap-共享迁移)。

网页端已接入时间线、回收站、搜索/筛选、继续加载、详情编辑、分类管理和附件的 Prepare → 直传 → Complete 流程；BFF 同时提供浏览器 Connect 合同和独立的 Streamable HTTP MCP 入口。附件只接受 JPEG、PNG、WebP、PDF，单个不超过 10 MiB，每条记录最多 20 个；附件下载由账号隔离的服务端鉴权：浏览器走服务端读取，MCP 通过 `timeline_get_attachment_download` 申请短时私有下载地址，两条路径每次都会重新校验归属和记录未回收，均不返回对象存储 key，也不提供永久公开链接。

### 网页端版面与视觉

网页端按 Stitch 设计稿“Timeline WebApp UI/UX Design”（Quiet Chrono Journal）实现，颜色和字号取自设计稿的语义色：纸张底 `#FFFEFA`、条目底 `#F6FAF2`、次级容器 `#EEF3E7`、深绿墨文字 `#2B4234`、次级文字 `#5C7162`、分隔线 `#DFE6D8`、主强调 `#527951`、克制砖红 `#BD715E`。层级只用纯色叠底和单像素浅边，不用厚阴影、渐变或毛玻璃；只有浮层（日期范围面板、记一笔面板）带一层很淡的环境阴影。字体先用 Plus Jakarta Sans，回退到系统中文字体，不请求第三方字体；日期、时刻、金额开启等宽数字。

- **左侧栏**（220px，窄屏收成顶部横条）：品牌“Timeline / 手账生活志”，时间线、分类管理、回收站、设置与 MCP 四个入口，底部为账号卡（昵称、已同步、退出登录）。
- **顶栏**（56px）：左侧“{年份}年 阳历记录本”，右侧检索手账（聚焦搜索框）、写手账和头像。
- **时间线页**：标题“时间线”与“记一笔”按钮；浅绿面板内放搜索框、分类筛选和日期范围（弹出面板填起止日期），有条件生效时下方出现“生效中”标签（可逐个移除）和“清除筛选”。列表以一根贯穿的细竖线为轴：月份徽标加分隔线，日期标题（今天带“今天”徽标），每条记录是“时间 · 节点 · 卡片”：有时间的记录是空心圆环节点，未指定时间的显示“未指定”和浅色小圆点；卡片显示标题、金额（`CNY 86.00`）、分类和地点标签、备注，以及附件行（图标、文件名、大小，点击打开，叉号删除）；悬停时右上角出现编辑和移到回收站的图标。640px 以下时间移进卡片、轴线靠左。回收站复用同一条轴，卡片提供“恢复”。
- **记一笔面板**：桌面宽度（≥1280px）在时间线右侧固定 420px 宽、不遮挡时间线，更窄时从右侧滑出并带遮罩；Esc、关闭和取消都会收起。字段为标题（必填）、日期与时间（时间可留空）及时区、分类、地点/店名、币种与金额、备注和附件区（点击或拖拽，显示上传进度，失败可只重试附件）。输入框浅底无边框，聚焦时为 1.5px 绿色轮廓。设计稿里“切换模拟状态”之类的演示控件、没有真实数据的内容不在正式页面提供。

当前限制：附件行用图标而不是缩略图，因为附件字节只能经 BFF 带会话读取，列表不会为每个附件预先下载；设计稿里的“重要事件实心节点”没有对应的记录字段，暂不提供。

分类首次访问时按用户幂等初始化为 22 个默认分类，并发首访只初始化一次，用户改名或停用过的默认分类不会被重建；自定义分类可创建、改名、停用和重新启用，`其他` 保持存在且不可改名或停用。金额区分“未填写”和 0.00（`amount_present`），填写金额时强制三位大写币种，只在金额存在时接受币种。

当前限制：v1 网页和 MCP 均不提供永久删除入口，永久删除能力只保留在服务端迁移兼容层。

### 并发与重放契约

除创建外，update、trash、restore、purge 必须携带正数 `expected_revision`。服务端在事务内执行带账号、opaque `entry_ref` 和当前 revision 条件的原子更新或删除；条件未命中返回冲突，事务回滚且不写 mutation receipt。响应和 replay snapshot 只含 `entry_ref`，不含内部数据库 UUID。`mutation_id` 必须是 8–128 个 ASCII 字符（`[A-Za-z0-9._:-]`），相同请求重放返回首次快照，不同请求复用同一 ID 会被拒绝。并发重复请求由 `(user_id, mutation_id)` 唯一约束抢占；落败事务回滚后读取已提交的首次 receipt，返回 replay 而非数据库唯一键错误。

迁移先启用 `pgcrypto`，再以随机字节回填 entry/media opaque refs，随后建立唯一索引和 mutation 表；回填失败或 CHECK 约束失败会使迁移事务回滚。生产发布必须先执行 `migrations/timeline/20261107180000_refs_mutations.sql`，再部署依赖新字段的服务。
