# 数据与地图说明

## 足迹数据结构

存储键为 `shanhai-travel-v1`，当前结构版本为 `1`。本地存储与导出备份使用同一结构。

```json
{
  "version": 1,
  "visits": [
    {
      "code": "330100",
      "name": "杭州市",
      "province": "330000",
      "color": "#719fc6",
      "date": "2026-10-12",
      "note": "西湖漫步"
    }
  ],
  "provinces": {
    "330000": "#4b937d"
  }
}
```

| 字段 | 含义与约定 |
| --- | --- |
| `version` | 数据结构版本，当前只接受 `1` |
| `visits` | 城市足迹数组，每个 `code` 唯一 |
| `code` | 城市或区县 ID，以字符串保存 |
| `name` | 当前区域索引中的显示名称 |
| `province` | 所属省级区域 ID，以字符串保存 |
| `color` | 五种足迹色彩之一 |
| `date` | `YYYY-MM-DD` 格式字符串，或空字符串 |
| `note` | 备注字符串，最大 1000 字符 |
| `provinces` | 省份独立标记，键为省级区域 ID，值为颜色 |

颜色映射为：山野绿 `#4b937d`、日落黄 `#e2af5c`、珊瑚橙 `#d88370`、海岸蓝 `#719fc6`、暮光紫 `#a08cbd`。

新探索省份的独立标记或第一条城市足迹，按全国已探索省份的记录代表色选择使用次数最少的颜色（每省计一次，独立标记颜色优先）；已有记录代表色时沿用。后续城市足迹选择本省现有城市足迹中使用次数最少的颜色。使用次数相同时按上述颜色顺序选择；新记录仍保存具体颜色值，数据版本保持为 `1`，既有手选颜色不重新计算。

业务行为见 [功能描述](features.md)。保存城市会先移除原 ID 的记录，再追加新记录，因此更新可能改变数组顺序；记录代表色优先取独立省份标记的保存颜色，否则取该数组中第一条所属城市记录，用于新记录的颜色分配。全国地图显示颜色另根据本地全国地图共同边界的邻接表，为全部 34 个省份确定固定配色：优先处理已有邻居颜色种类最多的省份，再按邻居数量及区域 ID 排序；排除邻居已用颜色后选择全局使用次数最少的颜色，同次数时按调色板顺序选择。只显示已探索省份的固定颜色，相邻省份不同色优先于颜色数量均衡，不承诺各颜色数量相等，列表与全国分享图片沿用同一映射；不写回存储，不依赖城市记录顺序或旧备份中的颜色，数据版本和导入校验不变。

## 本地存储与兼容性

- 启动时读取并校验本地 JSON（逻辑在 `src/lib/persistence.ts`），足迹变化后重新写入完整数据。
- 存储按浏览器和网站来源隔离，协议、主机或端口不同会使用不同存储；开发预览与正式站点不会自动共享记录。
- 后端 PostgreSQL/Redis/S3 基础设施已初始化，详见 [后端初始化](backend.md)。配置后端并登录后，足迹以服务端确认副本与本机待同步差异做三方合并：前端批量发送显式目标变更（城市足迹按区域 ID、省份标记按省份 ID，逻辑在 `src/lib/sync.ts`），不会整体覆盖云端；本地足迹迁移上云（F2）在前端把迁移结果作为一次目标变更交给同一同步引擎，不改变存储结构版本。
- 登录相关的浏览器存储：`shanhai-session-v1`（令牌、过期时间与用户信息）、`shanhai-cloud-v1:<用户 ID>`（`{saved, revision, confirmed, pendingBatch?}`，`saved` 为页面目标足迹，`confirmed` 为最后确认的祖先足迹，`revision` 对应祖先；差异表示待同步新增、编辑或删除，原有 `{saved, revision}` 缓存兼容为已确认副本。无法解析或任一副本校验失败时保留原始字符串并停止覆盖，供导出恢复）、`sessionStorage` 中的 `shanhai-oauth-pending-v1`（OAuth 回调校验）。登录期间不读写 `shanhai-travel-v1`；确认退出登录清除当前账号缓存及会话，不触碰本地足迹及其 `-unreadable-*` 副本；其他账号的未同步或损坏缓存不自动清理。每次编辑先保存完整目标及祖先再发送，保存失败拒绝编辑；重连先三方合并，无整体云端覆盖。同记录冲突需用户选择，旅行日期不充当修改时间。浏览器清理存储或用户确认退出会丢失未同步修改，应先导出备份。
- 读取失败（JSON 无法解析、版本不是 1、记录未通过校验）时保留原始缓存字符串，暂停自动保存，由用户选择导出原始数据、恢复可识别的记录或以空数据开始；后两者先把原始数据复制到 `shanhai-travel-v1-unreadable-<时间戳>`。缓存不存在或为空属于正常首次使用。这些副本不会自动清理，也不会被应用读取。
- 云端快照（F3）：服务端 `snapshots` 表保存某一 revision 下全部城市足迹与省份标记的不可修改副本（gzip 压缩的 `SnapshotData`，字段与前端 `Visit` / 省份标记一致，不含浏览器备份的 `version`）。快照用于恢复，不是备份文件格式：浏览器备份仍是 `version: 1`，快照不能导出。恢复时按当前区域索引重新校验，索引更新导致区域 ID、名称或归属不再被接受的快照无法恢复（区域索引版本映射属 F10，尚未实现）。保留期限与数量见 [后端初始化](backend.md)。
- 迁移相关存储：`shanhai-migrated-v1:<用户 ID>` 保存已迁移或已确认无需迁移的本机足迹指纹（条数与内容哈希）；不含足迹内容，退出登录不清除，本机足迹变化后指纹不再匹配，会重新提示。本机 `shanhai-travel-v1` 迁移前后不变。
- 金门 `tw-09020`、连江县（马祖）`tw-09007` 保留原 ID，省份归属改为福建 `350000`。版本 1 的本地缓存、导入备份和账号缓存的 `saved` / `confirmed` 中，原归属台湾 `710000` 的这两项在校验时规范化到福建；名称及其余字段仍须通过严格校验，重复 ID 仍拒绝，恢复可识别记录也使用相同迁移。颜色、日期、备注及独立省份标记均保留，不移动或删除独立台湾标记。两个账号缓存副本同时规范化，保留待同步差异及 revision，不产生虚假的归属冲突。
- 其他版本、名称或区域 ID 变更仍需设计兼容或迁移路径，保留已有足迹；未提供迁移的区域索引更新会使旧缓存校验失败并进入上述保护流程，而不是被清空。
- 写入失败会显示保存异常提示，内存中的记录仍可导出；页面关闭后不能保证保留未写入数据。

## 媒体数据（F4）

媒体不改变 `Saved` 或浏览器备份 `version: 1`，也不进入云端足迹快照与 revision。`media_objects` 在原有用户、对象 key、MIME、大小与状态之外，增加 `region_code`、`filename`、`upload_id`、`request_hash`、`upload_key`、`thumbnail_key`、`upload_expires_at`、`width`、`height`。新增字段均有默认值或可为空，保留旧元数据；`(user_id, upload_id)` 对非空 ID 唯一，旧记录的空 ID 不受唯一约束影响。状态为 `pending`、`ready`、`deleting`。

关联使用与地图相同的城市区域 ID，媒体不依赖城市足迹的数据库行，也不会随足迹取消、迁移或快照恢复级联删除。F5 的旅行关联尚未实现。只有服务端重新编码/验证后的文件可通过鉴权 RPC 获取，数据库不保存文件内容；PDF 保持原文件，照片转 JPEG 并生成缩略图，删除原元数据。

S3 key 在配置前缀下分为 `media/staging/<随机ID>`、`media/files/<媒体ID>`、`media/thumbnails/<媒体ID>`，不使用文件名、区域名或客户端提交的路径。签发前，预留元数据与独立 `media_cleanups` 工作项在同一事务内提交。清理队列只包含随机 key 和清理时间，不含账号身份，不随用户删除；24 小时后重新删除临时对象，处理已经注销账号但仍在途的上传。另需 S3 临时目录 2 天生命周期作为超长在途上传的兜底，配置见后端文档。

删除先把状态改为 `deleting` 关闭读取，再删对象，失败保留元数据供重试。每小时维护任务处理 `deleting`、24 小时未完成的 `pending` 和到期临时对象工作项。照片和附件没有浏览器持久化缓存，缩略图仅在窗口内使用 Blob URL，关闭后释放；JSON 备份不包含媒体，需单独下载。

## 备份导入导出

导出文件名为 `山海足迹-YYYY-MM-DD.json`。日期来自浏览器本地时间，文件内容为完整足迹数据。

导入最多接受 2,000,000 字节的文件，先解析和校验，再显示替换确认弹窗。确认后整体替换数据，不做合并；确认前提供导出当前备份入口。

当前校验包括结构版本、足迹数组、省份标记对象、城市与所属省份及名称的一致性、重复城市 ID、允许的颜色、日期字符串格式和备注长度。日期校验为格式检查，尚未额外验证实际日历日期。校验依赖当前 `src/regions.json`，区域索引更新可能影响旧备份兼容性。

## 地图文件与区域索引

| 文件 | 职责 |
| --- | --- |
| `public/maps/100000.json` | 全国省级边界及南海附图数据 |
| `public/maps/<省级区域ID>.json` | 对应省内行政区域边界 |
| `src/regions.json` | 省份 ID、全称、简称及下级区域 ID/名称，用于列表、搜索和备份校验 |
| `src/province-neighbors.json` | 全国地图共同边界邻接表，用于相邻不同色的固定配色 |
| `scripts/prepare-province-neighbors.mjs` | 从本地全国地图的共享边界线段生成邻接表 |
| `src/lib/cityMaps.ts` | 全国“按城市”着色时一次性加载全部省内地图；任一文件失败则整体失败，不显示不完整地图 |
| `src/lib/maps.ts` | GeoJSON 多边形方向归一化，适配 d3 的球面绘制 |
| `src/lib/tiles.ts` | 解析瓦片源环境变量并提供默认值 |
| `src/lib/coords.ts` | GCJ-02 与 WGS-84 坐标转换，用于把边界叠加到 OSM 底图 |
| `src/components/OsmProvinceMap.tsx` | 省内与全国可选 OSM 底图（Leaflet），按需加载 |
| `scripts/download-maps.mjs` | 根据现有全国地图下载省内地图并重建索引 |
| `scripts/prepare-taiwan.mjs` | 处理补充县市边界数据的名称、ID、中心点及多边形方向 |
| `scripts/split-fujian-regions.mjs` | 将补充边界中的金门、马祖拆入福建，并移除福州、泉州中的重复岛屿组件 |
| `scripts/check-maps.mjs` | 校验全国覆盖、省内索引一致性、ID 唯一性、多边形方向及投影路径 |

当前共有 34 个省级区域和 497 个可记录下级区域（福建 11、台湾 20）。全国城市统计将直辖市和港澳的 112 个区县合并为 6 个目的地，分母为 391；这只改变统计，不合并或删除足迹记录。数量是当前数据快照；更新后以 `npm run check:maps` 的实际结果为准。

普通区域 ID 来自数据中的 `adcode`，应用统一转换为字符串；补充数据使用 `tw-<county_id>`，例如台北市为 `tw-63000`，避免与其他区域 ID 冲突。`tw-` 表示数据源而非省份归属，迁入福建的金门与马祖仍沿用该前缀，避免破坏已有记录。

## 来源与边界限制

全国及除补充县市边界外的省内数据来自 [阿里云 DataV GeoAtlas](https://datav.aliyun.com/portal/school/atlas/area_selector)，省内下载接口为 `https://geo.datav.aliyun.com/areas_v3/bound/<adcode>_full.json`。

台湾县市及福建金门、马祖的补充边界来自 [ronnywang/twgeojson](https://github.com/ronnywang/twgeojson) 的 `twcounty2010.2.json`。其源数据为 2012 年县市边界；处理脚本将部分名称转换为简体，并把桃园县显示为桃园市，未据此重绘边界。下载全部省内文件后，拆分脚本将金门、马祖归入福建，从福州、泉州的 DataV 多多边形中移除对应的独立岛屿组件，避免重复点选；小组件按转换到 WGS-84 的球面中心与补充岛屿范围匹配，仅作用于这两个城市。全国地图原有福建轮廓不变。

直辖市和港澳提供区县数据，而不是常规省份的地级市数据。地图用于旅行可视化，下载快照可能与最新行政区划不同。

## OSM 底图（可选）

省内地图可通过开关改用 [OpenStreetMap](https://www.openstreetmap.org/copyright) 瓦片（`https://tile.openstreetmap.org/{z}/{x}/{y}.png`）作为底图，使用 Leaflet 绘制，并在首次开启时按需加载。偏好保存在独立存储键 `shanhai-basemap-v1`（`osm` 或 `off`），不属于足迹数据，也不进入导出备份。

- 默认关闭，关闭时不发起任何第三方地图请求，仍满足“运行时无需第三方地图请求或 API Key”；开启后才会请求瓦片，无需 API Key。
- DataV 边界为 GCJ-02 坐标，而 OSM 使用 WGS-84。开启底图时对除 `tw-` 补充数据（含福建金门、马祖）、香港、澳门以外的区域做 GCJ-02 到 WGS-84 的近似转换；转换仅用于底图视图，`public/maps` 数据与区域 ID 不变，SVG 视图仍使用原坐标。
- 瓦片通过 CSS 滤镜降低饱和度与对比度，使叠加的区域颜色和标签更清晰。评估过 Carto Positron 公共瓦片，目前需要 API Key，不可直接使用；更浅的底图建议改用自托管瓦片。
- 瓦片源可在构建时通过环境变量配置，未设置或格式无效时回落到上述 OSM 公共瓦片：`VITE_OSM_TILE_URL`（必须包含 `{z}`、`{x}`、`{y}`）、`VITE_OSM_TILE_MAX_ZOOM`（1–22 的整数；自定义地址默认 18，默认地址为 19）、`VITE_OSM_TILE_ATTRIBUTION`（附加署名，作为 HTML 显示，仅用于受信任的构建配置；OpenStreetMap 署名始终保留）。变量在构建时写入，修改后需重新构建；Docker 镜像通过 `--build-arg` 传入，当前 CI 工作流尚未传递这些参数。源码见 `src/lib/tiles.ts`。
- 全国地图的 SVG 视图使用圆锥投影并包含南海附图；开启 OSM 时改用 Leaflet 的 Web 墨卡托，不绘制南海附图，南海诸岛按原始坐标出现在底图上（三沙岛屿可拖动查看），海南主体视图范围固定为 `src/App.tsx` 中的 `NATIONAL_VIEW`。全国 OSM 的省份边界取自 `100000.json`，按城市着色复用各省内文件（首次开启时才加载，约 4 MB），并叠加省份边界线。对 GCJ-02 的转换与省内一致，台湾、香港、澳门及其下级区域不转换。
- 当前限制：开发阶段直接使用 OSM 公共瓦片，其[使用政策](https://operations.osmfoundation.org/policies/tiles/)不适合大流量生产场景，正式上线前需改为自托管瓦片或商业服务；香港、澳门边界未做坐标转换，台湾边界精度以数据源为准；边界与底图的行政区域线可能存在差异和偏移。

## 绘制与维护

浏览器从部署站点读取本地地图资源，通过 Vite 的 `BASE_URL` 拼接路径。运行时无需请求供应方接口或配置地图 API Key。

全国地图使用圆锥正形投影，省内使用墨卡托投影。全国相机范围按主体边界计算，南海相关附图单独绘制。海南省内 SVG 主图的缩放范围使用除三沙之外的本岛区域，三沙原始边界使用独立墨卡托投影绘制为附图（分享图片沿用此布局）；OSM 初始及重置视野也使用本岛边界，完整三沙图层仍保留。此调整不修改 GeoJSON、区域 ID 或足迹数据。数据先通过 `normalizeMap` 修正多边形方向，避免被 d3 解释为地球另一侧的大面积区域。

全国“按城市”着色复用各省内 GeoJSON，使用全国圆锥投影重新绘制，不新增数据文件或区域 ID，也不改变存储。省内数据与全国数据均使用 DataV 的 GCJ-02 坐标，台湾及福建金门、马祖的补充边界为 WGS-84，全国尺度下的偏移可忽略；省份轮廓仍取自 `100000.json`，与城市边界在海岸线或边界处可能有细小错位，海南三沙的岛屿按其原始坐标绘制。

邻接表由全国 GeoJSON 的共同边界线段生成（经纬度四位小数归一化，单点接触和隔海不算相邻），无运行时第三方请求。更换全国地图后运行 `npm run prepare:map-colors`，一并提交更新的邻接表；`npm run check:maps` 检查邻接表与全国边界一致，自动配色测试逐条验证共同边界两侧不同色。地图来源或精度变化可能导致配色变化，当前邻接识别依赖两侧使用匹配的线段采样。

更新省内地图时运行 `npm run download:maps`，完成后运行 `npm run check:maps` 与 `npm run build`，再检查受影响区域的可视效果及旧足迹兼容性。下载脚本依赖现有全国文件，当前不会自动刷新 `100000.json`；更新全国数据需单独替换该文件，再重建省内数据与索引。

下载失败可能留下部分已更新地图，需检查地图与索引一致性后再交付。地图文件、区域索引、来源说明和受影响的数量描述应在同一次变更中同步更新。

## F1 增量与幂等批次

账号缓存可选 `pendingBatch` 保存 `{id, revision, ops}`，发送前持久化整个请求；存在批次就算待同步，即使目标已回到祖先状态也不能当作已确认。重新打开先重放原批次，再三方合并最新增量，避免把自己的已确认中间状态误判为其他设备冲突。旧缓存缺少该字段时仍可读取，损坏批次阻止覆盖。

服务端 `footprint_changes` 保存用户范围内的 revision 与完整 upsert/删除操作，`sync_receipts` 保存请求 ID、哈希、结果 revision 和变更数量。实际变化逐项增加 revision；同一批次在一个事务中处理，失败整批回滚。重复 ID 必须对应完全相同请求，否则拒绝。日志与回执当前保留至账号注销，尚未实现裁剪策略。

`GetChanges` 分页读取，当前每页默认 200、最多 500；历史缺失或游标超出可用范围时要求完整快照。旧用户不回填历史；从新代码首次写入开始记录，旧逐条 RPC 同样记录日志。批量接口每批 1–600 项（足够一次迁移全部 497 个城市和 34 个省份标记），使用服务端当前 revision 校验，不使用旅行日期判定修改先后。前端一次读取最多 20 页，过长历史回退完整快照，失败不提交部分游标。

注销先暂停账号并清理对象，再通过数据库外键删除用户所有关联数据。完成回执仅保留注销会话令牌的哈希及 24 小时有效期，没有用户 ID 或足迹；过期后由每小时维护任务删除。浏览器备份仍为 version 1，F2/F3/F5 不在本次范围内。
