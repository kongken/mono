# 地铁足迹功能描述

> **管理入口已迁移（T8）：** 目录管理页面（城市、线路、车型、专题、导入/导出、审计、管理令牌）已迁入[统一管理控制台](../admin/features.md#metro-目录管理t8)，本站不再有 `/admin`。MCP 的独立来源白名单已由 T9 实现（BFF 的 `mcp.allowed_cidrs`，空名单拒绝所有 MCP 请求，见 [BFF 文档](../bff.md)）。
>
> **账号入口已收敛到 OzID（T11，[#89](https://github.com/kongken/mono/issues/89)）：** 地铁足迹没有自己的登录、注册、找回密码、资料、改密码、设备和注销表单，需要登录或管理账号时都进入 [OzID](../ozid/features.md)，成功后回到原页面；公开目录、公开主页、乘坐记录与骑行者资料的规则不变。见下“登录”与“账号入口收敛验收（T11）”。

地铁足迹是仓库的第二个产品：展示各城市的地铁线路与车型数据，登录用户标记自己坐过的线路，管理员维护目录，AI 客户端可经 MCP 辅助维护。本文只写用户可观察到的规则；决策与设计背景见 [规格](spec.md)，接口与实现见 [后端初始化](../backend.md#metro-服务地铁足迹) 与 [BFF](../bff.md)。

## 页面

| 路由 | 登录 | 内容 |
| --- | --- | --- |
| `/` | 否 | 探索页：目录概览（城市数、线路数、总里程）、按城市名称/slug（拼音）或运营线路名/代码/站名搜索，并与区域筛选取交集；城市卡片与车型专题入口 |
| `/cities/:slug` | 否 | 城市汇总与线路卡片（颜色、站数、里程、车型、编组、起终点、开通年份、状态）；默认只列运营线路；线路名/代码/站名搜索、编组筛选；登录后显示乘坐进度及“全部/已坐过/未坐过”筛选，标记/编辑在抽屉中保存 |
| `/topics` | 否 | 车型专题总览：所有专题的卡片 |
| `/topics/:slug` | 否 | 车型专题：命中线路数、里程、个人已坐过数量与百分比；按城市线路数量降序绘图（同数按 slug），按城市分组的线路台账及城市详情入口 |
| `/u/:handle` | 否 | 公开主页：资料、社交链接、按城市分组的乘坐记录、统计；未公开或不存在都显示同一个“不存在”页 |
| `/me` | 是 | 乘坐记录（按城市分组，可改年份、取消）、骑行者资料（公开主页的显示名称、handle 等）与公开设置，以及指向 OzID 账号设置的提示 |
| `/login`、`/account` | 否 | 已退役的旧入口：只有一页说明和“前往 OzID 登录”，没有任何表单，不跟随 `?next=` 等参数（见下“登录”） |

界面采用“Metro Archive”设计（Stitch 项目 MetroFootprint UI Design）：深绿主色与冷灰白底的卡片，标题 Space Grotesk、正文 Hanken Grotesk、编号与标签 JetBrains Mono（字体随应用打包，不从第三方域名加载）。桌面顶栏是“城市探索 / 车型专题 / 我的足迹”，手机上这三个入口在底部导航栏；顶栏右侧是账号昵称、OzID 账号链接和“退出”（匿名时是“登录”）。区域、车型分类和有序站名由目录管理员维护；缺失数据归“未分类”，不从车型代码猜测分类。乘坐记录仍只有可选年份，不记录具体日期或备注。

其他路径（包括已退役的 `/admin`、`/admin/<分区>`）显示“页面不存在”；本站没有管理入口，目录管理在统一管理控制台。

## 登录

账号由自建用户系统提供（邮箱＋密码），与山海足迹是同一个账号，所有账号页面都在 [OzID](../ozid/features.md)：登录、注册、找回密码、登录邮箱、账号昵称与头像、改密码、登录设备和注销账号。页面通过 `Me` 恢复会话（HttpOnly Cookie，只属于 BFF 的公开 API 主机，与 OzID 共用），前端不保存令牌或密码，也不通过产品自己的同源代理冒充共享会话。

- **入口。** 顶栏匿名时只有一个“登录”按钮，已登录时有“账号”链接（新标签页打开 OzID，无 opener）和“退出”。匿名访客点击“标记坐过”或“登录”只会前往 OzID 登录页，不会写入任何数据；地址只含应用 ID（`app_id=metro`）和 `return_path`，不含令牌、邮箱或查询串。没有配置账号中心（构建时缺少 OzID 地址）的开发环境里，登录提示“账号中心尚未配置，暂时无法登录。”，不发起任何账号请求。
- **返回。** 登录成功后回到发起登录的页面。可返回的页面是封闭名单：起始页 `/`、`/me`、`/cities/<slug>`、`/topics`、`/topics/<slug>`、`/u/<handle>`（段只含 ASCII 字母、数字与 `-._~`，1–64 位）；产品先问 BFF 该路径是否已登记且与 OzID 将使用的完全一致，答案不符、BFF 不可达或超过 3 秒就回到起始页。查询串和片段从不带入。BFF 的注册表是 `navigation.apps.metro.paths: ["/me", "/cities/*", "/topics", "/topics/*", "/u/*"]`。
- **会话以 `Me` 为准。** 只有 `Me` 返回“未登录”才表示已退出；网络失败、超时、服务不可用都不是退出：已知账号时保持显示并提示“暂时无法确认登录状态，先按已登录的账号显示”，从未确认过时显示同样的提示和“重新检查”，两种情况都不会出现登录按钮或跳转。页面重新可见、获得焦点或网络恢复时（至多每 5 秒一次）会再问一次 `Me`：在 OzID 或另一个标签页里退出、改密码或换了账号，这里下次核对时显示“你已在其他页面退出登录，或登录已失效”或“账号已在其他页面切换为「…」”，并按新账号重新读取乘坐记录；不会因此循环跳转。
- **不串写。** 所有需要登录的请求带 `X-Kongken-User`（页面当前认为的账号）；共享 Cookie 已换成另一个账号时，BFF 拒绝该请求（401），页面随后核对账号并切换，前一个账号的操作不会写进后一个账号的数据。写请求遇到“CSRF 令牌被其他标签页或 OzID 替换”的带标记拒绝时，换新令牌后按原样重放一次（同一消息体、同一账号头），其他任何拒绝都不重放。
- **退出。** 顶栏“退出”只撤销当前 BFF 会话；失败时提示“退出登录没有完成，请检查网络后重试。”，不当作已退出。
- **旧入口。** `/login`、`/account` 显示“登录已迁移到 OzID”或“账号设置已迁移到 OzID”和一个按钮，进入页面时地址栏的查询串与片段被清除，不自动跳转，不接受任何返回地址（`?next=https://…` 被忽略）。
- **旧邮件。** `/account/verify-email`、`/account/reset-password` 只服务升级前发出的邮件：令牌在 URL 片段中，页面立即读入内存并从地址栏清除，不写浏览器存储，不启动应用（没有 `Me` 或目录请求），打开页面本身不消耗令牌；“去登录”进入 OzID（返回到 BFF 为该邮件确认过的页面）。新邮件的链接直接指向 OzID。
- **与骑行者资料区分。** `/me` 的“骑行者资料与公开主页”是地铁足迹自己的资料：主页显示名称、handle、公开开关、头图与社交链接，只影响 `/u/<handle>`；它不是账号昵称或头像，登录不覆盖它，也不会因账号昵称变化而变化。账号昵称与头像、登录邮箱、密码、设备和注销在 OzID，`/me` 底部有一句提示和链接。升级前未完成的账号注销，顶栏提示“账号注销尚未完成”和“前往 OzID 重试注销”（OzID 的关闭账号页）。

## 乘坐记录与公开主页

- 只能新标记运营中或暂停运营的线路；重复标记同一条线路只有一条记录，年份以最后一次为准；不带年份的标记会清空年份。取消未标记的线路也成功。
- 年份是 1900 到今年的整数，留空表示不记年份。
- 登录后，城市/专题页的“标记坐过”“编辑足迹”及 `/me` 的“编辑年份”打开同一个编辑器（手机底部抽屉、桌面弹窗）。打开、取消、Escape 和快捷填写均不写入；只有“保存记录”写入年份，清空年份后保存仍保留乘坐记录；“移除此线路足迹”单独取消标记。保存失败保留草稿并允许重试；提交中禁用重复操作。编辑器支持键盘焦点约束和关闭后回到入口；筛选后入口消失则回到正文。
- 乘坐记录尚未加载或读取失败时，不把未知状态当作“未坐过”，编辑按钮暂不可用并提供重新加载。会话切换仍由 `Me` 和账号请求头隔离。
- 资料默认私有。设置 handle（3 到 32 位小写字母、数字或下划线）并打开公开开关后，`/u/<handle>` 才可见；handle 被占用时提示冲突。头图最多 8 个，只接受 `https` 地址；社交链接可填用户名或 `https` 链接，其他协议一律不显示。
- 注销账号在 OzID 完成（需要最近 15 分钟内输入过密码）；它同时清理山海足迹（如有）和地铁足迹的云端数据并删除账号本身；失败时账号保持“删除中”，可在 OzID 重试。`/me` 没有单独的“删除我的数据”。

## 目录数据规则

- 城市用 `slug`、车型和线路用 `code`、专题用 `slug` 标识；线路颜色必须是 `#RRGGBB`。
- 城市 `region` 可空或取 `east/north/south/southwest/central/northeast/northwest`。线路 `vehicle_type` 可空或取 `a/b/l/rubber/other`；`station_names` 为起点到终点的完整有序列表，可空；非空须与 `stations` 相等、最多 999 站，每站 1–64 字且无首尾空白或控制字符。首末站用于展示起终点，全部站名参与搜索；空列表不推断站名。
- 城市页的编组条件与乘坐状态、搜索同时生效：6A/6B 为车型 a/b 且 `cars` 或 `cars_addition` 为 6；8A 为 a 且相应编组为 8；特种/胶轮为 l/rubber/other；未分类为 `vehicle_type` 空。无匹配时可重置全部条件。
- 管理页、MCP、`metro-catalog/1` 导入导出、审计与公开读取均包含这些可选字段；旧目录未填写时仍可浏览并归未分类。站名列表用于目录展示和检索，不提供换乘规划。
- 图片只用 `<img>` 加载，地图 SVG 不内联到页面（避免脚本注入）；所有图片和链接地址只接受 `https`。
- 目录在浏览器内存中缓存，并用目录版本（`known_version`）校验：版本未变化时不重新下载。管理员写入或导入后缓存立即失效。
- 被线路引用的城市或车型不能删除；有乘坐记录的线路不能删除，先改为“已停运”。

## 管理后台（已迁入统一管理控制台）

以下规则不变，页面现在位于控制台的“地铁目录”分区（`/metro/...`，只在管理周界内可用，见 [控制台功能描述](../admin/features.md#metro-目录管理t8)）；本站不再提供这些页面。

| 分区 | 功能 |
| --- | --- |
| 城市、线路、车型、专题 | 服务端搜索与分页（“加载更多”）的表格；新建、编辑、删除。编辑携带 `expected_revision`：别人先改过则提示“已被他人修改”，可一键刷新并重新编辑。字段错误显示在对应字段 |
| 导入 | 粘贴或选择 `metro-catalog/1` JSON（最大 1 MiB）：停止输入后自动做 dry-run 预览（新增/更新/无变化数量与逐条错误），有错误时“确认导入”不可用；确认后才写入，全有或全无，不删除文件里没有的记录 |
| 导出 | 下载整个目录的 `metro-catalog/1` JSON，可原样导回 |
| 审计日志 | 按对象、渠道（`web`、`mcp`）、执行者、时间过滤；MCP 写入带令牌 ID |
| 管理令牌 | 创建（名称、权限只读或读写、有效期 7/30/90 天）、列表（名称、权限、过期时间、状态）、吊销；明文只在创建后显示一次，刷新后不再可见；页面给出 MCP 端点地址和客户端配置示例 |

管理会话要求在 `auth.admin_session_max_age`（默认 12 小时）内登录，过期后管理操作要求重新登录。

## MCP

管理员在“管理令牌”创建令牌后，MCP 客户端以 `Authorization: Bearer <令牌>` 访问 `POST /mcp/metro`（无状态 Streamable HTTP，无 Cookie、无 CORS）。令牌只存摘要，最长 90 天，每人最多 10 个有效令牌，吊销立即生效；按令牌限流（默认每分钟 60 次）。令牌带创建时的角色快照，但每个工具调用都会向 usersrv 复核：账号非 active、账号的认证版本（改密码、禁用、授予/撤销角色、注销都会改变它）与令牌创建时不同，令牌立即失效；创建者当前已没有 `metro-admin` 时调用返回 `PERMISSION_DENIED`；撤销角色后重新授予不会让旧令牌复活，需要重新创建。

- 工具（20 个）：只读 `metro_list_cities`、`metro_list_lines`、`metro_list_rolling_stocks`、`metro_list_topics`、`metro_get_entity`、`metro_export_catalog`、`metro_list_audit_logs`；读写额外有各类实体的 `metro_create_*`、`metro_update_*`、`metro_delete_*` 和 `metro_import_catalog`。
- 安全约束：`metro_import_catalog` 的 `dryRun` 默认 `true`，必须显式传 `false` 才写入；更新和删除必须带 `expectedRevision`（先读再写）；校验失败以工具错误返回，含字段级信息，便于模型修正后重试。MCP 与网页走同一个内部管理接口，规则、并发控制和审计完全一致。

### 账号入口收敛验收（T11）

范围：[#89](https://github.com/kongken/mono/issues/89)，基线为 T10（`aa755cd`）。普通账号的登录、注册、找回、设置和失效入口全部在 OzID，产品里没有账号表单；公开目录、公开主页、乘坐记录与骑行者资料的权限和数据规则不变；不等待 metro 后台迁移（管理入口在统一控制台，本票不改）。

- **分层验证。**

- **反向检查（变异）。** 单元与模拟 BFF 层在开发时对返回名单、退出判定、账号头等关键保护做过手工破坏性验证（未保存为用例）；真实栈另做了两项并确认对应用例失败：把任何 `Me` 失败都当作未登录（网络失败场景两个视口都失败）、关闭 CSRF 重放（两个令牌场景失败）。
- **部署变化。** metro 前端自 T11 起没有同源 `/api` 代理：镜像和本地构建必须给出绝对的 `VITE_API_BASE_URL` 与 `VITE_OZID_ORIGIN`，否则构建失败（`vite dev` 没有这两项时回退到本机 `/api` 代理，只用于本地开发，登录显示“账号中心尚未配置”）；BFF 的 `navigation.apps.metro.paths` 需要登记上述返回页，CORS 增加 metro 站点 origin（见[部署文档](../deployment.md)）。
- **已知限制。** 真实栈测试用 `page.clock` 推进时间触发核对，没有等待真实的 5 秒；“不循环”只在测试的观察窗口内成立（有限的时钟推进与一次再核对），不是对任意时长的证明；标签页之间没有 BroadcastChannel，OzID 里的变化只在本页重新可见、获得焦点或网络恢复时被发现；改密码在 OzID 的链路由 OzID 自己的测试覆盖，这里用“OzID 退出登录”覆盖产品的同一路径（二者对产品都是 `Me` 返回未登录）；`metro-web` 镜像的构建与运行检查只在 CI（有 Docker 的环境）里执行，生产代理（Nginx/Caddy）的 CORS 与 Cookie 行为按示例配置给出，没有在真实生产代理上验证；在同一页面上等待“CSRF 令牌被替换”的时机是用请求拦截复现的（令牌在发出前一刻被另一标签页替换），不是真实的竞态；分支保护是否把 `metro-browser`、`metro-web-image` 设为必需检查无法从仓库确认；管理入口仍在统一控制台，旧账号入口只保留受控说明页与限时过渡的旧邮件落地页，本票不关闭任何未迁移的管理入口。

## 当前限制

- 在线应用，没有离线与本地持久化。图片和地图是外链 `https` 地址，不支持上传。
- 只有一个管理员角色 `metro-admin`，由 usersrv 保存，只能用 `usersrv-admin` 授予或撤销；BFF 每次请求和每次 MCP 工具调用都读取当前角色，撤销立即生效（见管理会话期限）。
- 令牌的创建与吊销只写 BFF 日志，不进入目录审计日志。
- 目录没有批量改状态的接口，可通过导入同 `code`、新 `status` 的 JSON 完成。
- 产品名称、域名和主题色是工程内部暂定值。
- 部署与来源（T12）：`metro-web` 与示例网关不再代理同源 `/api/`，账号写只接受 OzID 来源，`Me`、CSRF 与退出照常；整体验收见 [整体验收](../ozid/acceptance.md)。
