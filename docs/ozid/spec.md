## 1. 目标与已确认决策

| 决策 | 已确认结论 |
| --- | --- |
| 用户中心品牌 | **OzID**，面向用户的统一账号系统，不只是登录页面 |
| 用户中心前端 | `apps/ozid`，包名 `@kongken/ozid`，部署示例 `https://id.example.com`（非真实地址）；正式地址由私有部署配置给出 |
| 统一管理控制台 | 独立前端 `apps/admin`，包名 `@kongken/admin`，部署示例 `https://admin.example.com`（非真实地址）；不放在用户中心的 `/admin` 下，也不是只管理账号的“OzID Admin” |
| 账号后端 | 复用现有 usersrv、用户 UUID、密码/邮件/角色/认证版本；不为产品品牌重命名后端，不增加第二个账号库 |
| 公网入口与会话 | 继续使用同一个 BFF，部署示例 `https://api.example.com`（非真实地址）；前端直接携带 credentials 请求它，Cookie 只属于 API 主机 |
| 首版接入 | 山海足迹、地铁足迹、OzID 和管理控制台；普通账号默认能使用两个产品的普通功能，无逐应用审批 |
| 后续范围 | 面向用户自己的其他项目；首版只承诺同站点、同 BFF 的接入，不开放第三方开发者自助接入 |
| 登录与入口 | 邮箱＋密码；产品的登录、注册、找回密码、邮箱落地页和账号设置收敛至 OzID，产品只保留业务设置；不重新引入 Logto |
| 后台范围 | 用户查询、普通账号状态、允许管理的角色、安全审计；本次一起迁移已有 metro 管理页面，不长期保留两套后台 |
| 后台安全 | 管理前端与全部浏览器管理接口按来源 IP 白名单限制；另有角色鉴权，敏感操作需近期密码认证 |
| MCP 安全 | 同样按 IP 限制，单独使用机器客户端白名单；空白名单拒绝，仍校验令牌、scope、角色和账号状态 |
| 角色 | `ozid-admin` 与 `metro-admin` 独立、不继承；前者仅 CLI 授撤，网页仅可授撤后者；不能通过网页禁用平台管理员、改他人密码、冒充或代他人注销 |
| 注册与邮箱 | 沿用邮箱验证的开放注册及关闭注册开关；首版不增加修改登录邮箱 |
| 退出 | 结束当前浏览器共享会话，所有接入应用在下次校验时观察到；其他设备保留；新增“退出其他设备” |
| 返回位置 | 从业务发起，登录后安全返回原业务页面；直接访问 OzID 则进入账号概览；注册/重置成功不自动登录 |
| 域名 | 当前域名是部署选择，不写死在业务源码；通过前端构建参数、服务端及部署配置替换，应用 ID 不随域名变化 |
| 数据安全 | 延续 usersrv 第一版不导入历史 Logto 数据的约定，但本次不重置现有 usersrv 账号或产品数据；保护本地足迹及未同步缓存，不自动清库/清桶/清浏览器存储 |

## 2. 当前事实、增量与非目标

### 当前已实现（基线，T1 之前的状态；T1、T2、T3 的现状见 [功能描述](features.md)，T4 见 [控制台功能描述](../admin/features.md)）

- `usersrv` 是唯一账号来源：邮箱规范化、Argon2id、注册验证、登录、改密/重置、资料、认证版本、角色 CLI、四种邮件 adapter 与加密 outbox。
- BFF 持有 HttpOnly Cookie 会话和注销工作流；每个受保护请求以及 MCP 工具调用复核 usersrv 的状态、`auth_version`、角色；产品服务只认内部凭证。
- `packages/account` 已包含账号客户端、表单、校验、错误处理和邮件落地页。trip-map 使用 `AccountDialog`，metro 有 `/login`、`/account`；各自也接收邮件链接。
- （基线描述；T8 起这些页面已迁入统一控制台，`apps/metro/src/pages/admin/` 已删除，旧 `/admin` 路由退役，见 [控制台功能描述](../admin/features.md#metro-目录管理t8)）metro 当时已有城市、线路、车型、专题、导入/导出、目录审计和管理令牌页面（`apps/metro/src/pages/admin/`）；其业务接口和 MCP 已实现。
- （基线描述；T4 起角色白名单为 `metro-admin` 与 `ozid-admin`，并有控制台、用户查询和管理周界，见 [控制台功能描述](../admin/features.md)）usersrv 当时的角色白名单只有 `metro-admin`，角色/账号状态只可通过 CLI 管理。当前没有 OzID 独立前端、统一控制台、网页用户管理接口或管理 IP 白名单。

### 本次交付增量

1. 两个可独立构建、部署的前端及其路由、响应式界面、镜像和部署示例。
2. 统一的导航目标校验、登录返回、邮件落地与跨应用会话恢复；账号表单只在 OzID 提供。
3. usersrv 增加 `ozid-admin`、受保护的用户管理能力及审计；BFF 逐方法适配，不直连账号库。
4. 浏览器管理接口、控制台站点和 MCP 的端到端 IP 防护；规则覆盖原接口和所有可到达的代理入口。
5. 迁移 metro 管理界面但不重写领域规则；补齐跨应用、账号切换、改密、退出和注销的数据保护。

### 非目标

- OAuth/OIDC/SAML、跨根域或独立 BFF 的单点登录、第三方开发者平台、自助应用接入、应用授权审批。
- 根域 Cookie（如示例 `Domain=.example.com`）、前端 Bearer 长期登录、自创一次性登录票据/认证码交换协议。
- 修改邮箱、账号合并、外部身份绑定、手机号/社交登录、Passkey、MFA/TOTP/恢复码；上一轮曾提出的 MFA 并未纳入本版。管理后台不能脱离 IP 限制直接开放公网；若要开放，另评审 MFA 等风险控制。
- 用户管理后台中的直接设密、查看密码/密码哈希、冒充登录、代用户注销、批量用户导出、自定义角色编辑器。
- 邮件模板编辑、厂商配置 Web UI、送达追踪或替换 usersrv 第一版邮件机制；F12 通知邮箱继续独立，不自动使用登录邮箱。
- 新后台后端服务/数据库、将所有产品审计集中到一张表、重新实现 metro CRUD、微前端平台或通用插件框架。
- 地图、足迹/备份格式、地铁普通业务、现有本地数据兼容与未同步队列的重写。

## 3. 架构与职责

```text
OzID 用户中心     id.example.com       ─┐
统一管理控制台    admin.example.com    ─┤
山海足迹         产品子域名            ─┼─ credentials → api.example.com / BFF
地铁足迹         metro 子域名     ─┘                    ├─ usersrv（内网）
                                                       ├─ tripmap（内网）
MCP 客户端 ─ 机器 IP 白名单 + Bearer → BFF /mcp/metro    └─ metro（内网）
```

| 模块 | 拥有的规则/数据 |
| --- | --- |
| OzID | 登录与自助账号页面、登录导航上下文、共用账号的清晰文案；不持有密码/会话持久化副本 |
| 管理控制台 | 按实际角色展示用户管理和 metro 分区；只调用 BFF，不拥有领域规则或管理员账号表 |
| BFF | 会话/CSRF/CORS、IP 防护、受控导航、管理认证时效、注销编排、管理令牌、错误映射 |
| usersrv | 账号唯一性、密码/角色/状态/版本、账号邮件、用户管理业务不变量及账号安全审计 |
| metro / tripmap | 各自业务规则、数据和领域审计；不读取 usersrv 数据库 |

- 不改变 Go 业务 import 隔离：BFF 通过生成的 `usersrv.v1` / `metro.v1` 调用，不能 import 其内部业务包；`internal/platform` 不依赖业务。
- 共用账号契约仍在 `proto/bff/v1/`；拟新增共用用户管理契约也在该包，而不是 `bff.metro.v1`。内部管理契约放 `proto/usersrv/v1/`；metro 契约继续独立。
- 前端复用 `packages/account`、`packages/ui`、生成的 `packages/api-client` 和 phosphor 图标。将 metro 管理实现迁入 `apps/admin` 并改应用依赖；不让 `apps/admin` import `apps/metro`，不用复制两套长期维护的代码。
- 各前端有独立配置、构建产物和部署；控制台 bundle/路由不放入 OzID 用户端。不新增一个既承载用户中心又承载后台的前端。

## 4. 可配置域名与部署约束

### 4.1 配置归属（拟定 interface）

| 位置 | 配置内容 | 生效方式 |
| --- | --- | --- |
| 前端公开构建参数 | BFF API base、OzID base、管理控制台 base、稳定应用 ID | 构建时写入静态产物，变更需重新构建部署；没有承诺运行时热加载 |
| BFF | 应用 ID → 精确 origin/允许返回路径/默认路径；OzID origin；控制台 origin；精确 CORS；浏览器管理与 MCP CIDR；受信代理及密码认证时效 | 服务端配置，启动校验；变更按现有配置加载方式重启 |
| usersrv | 中央账号邮件 origin、允许来源应用和导航上下文、角色白名单相关配置 | 服务端配置，变更重启；不再让产品各自产生邮件落地页 |
| 部署 | DNS、TLS、Ingress/反代 host、前端 IP 防护、BFF 的受信网络入口 | 随部署更新，不修改业务源码 |

可保留 `VITE_API_BASE_URL` 等现有参数；新增变量及 YAML 字段在实现时定名，并同时更新类型、配置校验、example、Docker build args 和文档。参数只含前端运行所需的公开地址，不含 Secret。**公开仓库、Issue、PR 与配置示例只使用保留示例域名或占位符，不记录真实部署域名、IP 白名单或凭据；真实值由私有构建/部署配置注入。** 禁止只提供环境变量示意却遗漏镜像构建参数传递；Butterfly YAML 当前不会自动展开 `${VAR}`。

### 4.2 不变量

- `id.example.com`、`admin.example.com`、`api.example.com` 仅为保留示例，均不代表真实部署地址；正式值通过私有配置注入，业务源码、路由守卫、模板不嵌入真实域名。测试使用独立保留测试域名。
- 稳定应用 ID 首版为 `ozid`、`admin`、`trip-map`、`metro`；应用 ID 不是 hostname、Cookie domain 或可任意填写的跳转 URL。
- 所有启用前端必须使用同一个规范 API origin，不保留产品各自同源 `/api` 代理来冒充共享会话；用户中心/控制台也不把 API Cookie 留在自己主机上。
- 生产 HTTPS、Secure Cookie、同一 schemeful site、允许的受信任子域名；**同根域不等于同源**。CORS 为精确 origin（协议、域名、端口），不能使用 `*` 或任意回显。
- BFF 的 `kongken_sid` 保持 host-only、HttpOnly、SameSite=Lax、Path `/`，不设置根域 Domain。CSRF 使用响应体 token 与 `X-CSRF-Token`，不要求 OzID 读取 API 主机 Cookie。
- 工程默认：登录、注册/重置、重新认证、资料/密码修改、设备管理写入和注销等集中账号写 RPC 仅接受精确 OzID Origin；`Me`、CSRF 签发和幂等退出按已登记应用开放，业务正常读写仍按产品来源允许。不能把“页面迁走”误当作后端来源策略已收敛；账号写方法仍需 CSRF/会话或其明确的匿名策略。
- 整组迁到新的同根域子域名属于配置变更；拆到无关根域或多个 BFF 不属于本版“改个域名就支持”的能力。
- BFF 导航 registry 的业务 origin 与 usersrv 的邮件 origin 是不同概念：邮件始终落 OzID，业务登录返回才指向来源应用，不能通过把二者混用而返回错误站点。

### 4.3 域名切换

部署步骤要同时列明前端重建、服务端 registry/CORS/邮件地址、DNS/TLS/路由及可信代理检查；不同层不允许静默使用旧默认域名。更换 API 主机后旧 Cookie 不会自动转移，应预告重新登录。

已发邮件中的旧 origin 不会自动改写：保留受控旧落地入口至少覆盖尚有效的注册/重置令牌期限，或明确要求用户重新申请；不新增泄露 fragment 的通用重定向器。切换前后都要验证 IP 防护和拒绝旧来源，不能为过渡使用通配 CORS。本次不触碰现有账号 UUID 或业务数据。

## 5. 页面与信息架构

以下为目标路由，所有业务前端旧入口仅可做受控兼容跳转，不再渲染旧表单。

### 5.1 OzID（`apps/ozid`）

| 路由 | 内容/访问 |
| --- | --- |
| `/` | 已登录账号概览：基础昵称、本人邮箱、安全设置入口；未登录引导 `/login` |
| `/login` | 邮箱密码登录，已有有效会话可继续返回已校验来源；显式切换账号需先退出共享会话 |
| `/register` | 申请注册、统一中性应答、发送/冷却/限流/注册关闭/网络错误 |
| `/forgot-password` | 找回密码申请、统一应答和冷却 |
| `/account/verify-email` | 邮件验证后设置密码及昵称，成功不自动登录 |
| `/account/reset-password` | 设置新密码，成功不自动登录 |
| `/profile` | 本人邮箱只读、基础昵称/头像；不编辑产品的骑行者资料 |
| `/security` | 修改密码和必要的重新认证；不用 Cookie 更新时间代替密码校验时间 |
| `/sessions` | 本人有效会话、撤销指定会话、“退出其他设备”；只展示现有元数据，不虚构设备名称/IP 地理定位 |
| `/close-account` | 全部产品的数据范围、重新认证、明确确认、注销进度及失败重试 |

登录、注册、找回页清楚显示品牌 OzID，说明账号在已接入产品共用；不显示 Logto，亦不暗示用户是在只注册某个产品。表单保留正确 autocomplete、粘贴/密码管理器、键盘操作、字段错误与处理中状态；桌面和手机都能使用。

邮件落地页保留第一版的特殊启动过程：先读 fragment 到内存并立即清地址栏，不加载业务应用/分析脚本，不保存令牌到浏览器存储；GET 不消费令牌，显式提交才验证；no-store、no-referrer、受控脚本来源。刷新后需要重新打开邮件，不能为“保存返回位置”把令牌一并持久化。

### 5.2 统一管理控制台（`apps/admin`）

| 路由 | 权限/内容 |
| --- | --- |
| `/` | 先过 IP 限制，再按有效会话和角色显示可用分区；匿名跳 OzID 登录，已登录无管理角色显示无权限，不循环跳登录 |
| `/users` | `ozid-admin`：分页、过滤、用户查找 |
| `/users/:id` | `ozid-admin`：允许展示的账号状态/角色、允许的操作与安全记录；不显示私有产品数据 |
| `/audit/users` | `ozid-admin`：账号安全与管理审计 |
| `/metro/cities`、`/metro/lines`、`/metro/rolling-stocks`、`/metro/topics` | `metro-admin`：迁入现有列表与 CRUD |
| `/metro/import`、`/metro/export` | `metro-admin`：迁入导入预览/确认与导出 |
| `/metro/audit`、`/metro/tokens` | `metro-admin`：迁入目录审计及管理令牌 |

控制台提供“管理 OzID 账号”链接跳用户中心，不再出现自己一套登录/改密/注销表单。导航菜单按实际角色显示；直接打开没有权限的路由仍被拒绝。两角色都没有时不能访问任何管理数据；有两个角色才显示两个分区，不把 `ozid-admin` 自动当作超级业务管理员。

页面未保存内容遇到导航/失效时保留当前编辑内容并提示，不能在重新认证后自动重放一份已经过时的管理写入。管理接口返回的 revision/版本冲突要要求刷新后确认。

## 6. 统一登录与返回流程

### 6.1 导航 interface（工程约束）

- 产品只传稳定 `app_id` 和 `return_path`，BFF 根据 registry 解析出 OzID 入口和返回目标；不接受客户端给出的绝对 return URL、任意 issuer、API 地址或 origin。
- 拟新增共用匿名只读 `ResolveNavigation` 能力，返回校验后的导航目标；读取没有用户数据，不建立/交换会话。它不是 OAuth state 或登录票据协议；能构造一个返回参数不能获得身份。
- `return_path` 首版指规范 pathname：必须 `/` 起始，符合该应用精确路径或显式路径规则；禁止 `//`、反斜线、控制字符、`.`/`..` 段、编码绕过、scheme、query 和 fragment。不在导航参数携带备注、搜索词、密码、令牌等敏感数据。
- 非法/未知应用或路径明确拒绝，不先跳不受控地址；没有来源上下文时默认 OzID `/`。管理目标只允许配置的控制台页面，不通过用户输入扩大 IP/CORS 白名单。
- 首版恢复业务页面的 pathname；页面筛选/草稿仍由业务自己的状态管理处理，不承诺把任意 query/fragment 带过账号流程。

### 6.2 浏览器闭环

1. 产品在离开前完成本机修改持久化；保存失败或待处理数据无法安全保留时，先提供导出/取消，不能直接跳走丢失数据。
2. 用户顶层导航到配置的 OzID。OzID 校验导航上下文，调用同一 BFF 的 `Me`；无会话显示登录，已有有效会话可返回合法目标。若用户要切换账号，明确提示退出影响整个浏览器共享会话。
3. OzID 调用既有 `LoginWithEmail`，BFF 校验密码并生成 API host-only Cookie，不把令牌返回页面或放进 URL。
4. 成功后只跳服务端校验过的来源页面；业务页面重新 `Me`，以 BFF Cookie 确定身份，再恢复该 UUID 的业务状态。不得根据 URL 的 user ID、昵称或缓存认定已登录。
5. `X-Kongken-User` 继续约束已确定身份的业务请求；迟到响应、换账号或另一个应用改变 Cookie 不能让 A 的缓存写到 B。

业务页面在启动、重新可见/获得焦点及认证错误时校验会话，合并重复请求。不同 origin 不能假设共享 BroadcastChannel/localStorage 事件，也不为会话同步扩大 Cookie Domain。网络/usersrv 故障和真实失效分开处理：前者可重试，不把它当作退出并删除缓存。

### 6.3 注册、找回与邮件上下文

- 复用第一版“先验证邮箱，再设置密码”的流程、令牌用途隔离、有效期、限流、四种 adapter 和 outbox，不新增免密登录。
- 新申请的所有账号邮件统一以配置的 OzID origin 为落地地址；来源产品上下文只控制后续返回，不能控制邮件 origin。扩展当前 `auth.apps` 校验及 `app_id` 含义时必须同步用户端、BFF、usersrv，不能只给旧 map 添加一项就声称完成集中化。
- 需要跨“申请→邮件→设置密码→再次登录”保留的应用 ID/path，应经 BFF 校验后绑定挑战/邮件流程，允许在另一浏览器打开邮件；完成注册/重置后可返回该合法上下文。只保存导航信息，绝不把用户尚未设置的密码写队列。
- 如果链接没有来源上下文或其目标已退役，完成操作后停留 OzID 并提供安全的登录入口；不能让令牌消费后的返回错误变成“账号没有创建”。
- 注册/重置完成不自动登录，不因浏览器已有另一个账号的 Cookie 而把新账号数据写入旧账号。旧产品邮件页过渡必须保持 token 在内存/fragment，不经 query 或日志转发；最终不长期运行两套表单。

## 7. 账号设置、会话与数据保护

- 全部自助能力仍调用 `bff.v1.AuthService` / `UserService`，不新增另一个认证来源；基础资料与 metro 的骑行者资料继续区分。
- 显式“退出登录”撤销当前 BFF 会话；所有连接到同一 API 的应用在下一次校验观察到，其他设备保留。不承诺跨 origin 的立即 UI 推送，也不承诺 OzID 能直接清掉产品域名 localStorage。
- 新增 `RevokeOtherSessions`：原子撤销本人除当前会话外的有效浏览器会话，幂等；不能循环调用列表来漏掉并发会话。它不改变密码/auth_version，也不吊销 MCP 令牌；操作之后新建立的会话仍可正常存在。
- 改密/重置继续增加认证版本，使所有浏览器会话和既有管理令牌在下次复核失效，含当前会话；旧版本不能靠重新认证升级为有效。
- 当前产品明确发起退出时，先按已有导出/确认规则处理自己的未同步修改；其他应用被动发现会话失效时保留缓存，不能把“别处退出了”当作删除本地数据的授权。账号中心直接退出也不触发跨域清理命令。
- 迁移后产品的失效提示改为“前往 OzID 重新登录”和导出/重试，不再内嵌密码框。恢复登录后按 UUID 恢复原缓存、队列和冲突处理，不跳过原有同步保护。
- 注销仍由 BFF 持久化工作流编排、原 Cookie 限定状态/重试、全产品清理失败可恢复；页面明确不是仅删除某产品数据。OzID 的注销落地不能提前清除用于重试的 Cookie，也不能擅自取消进行中的注销。
- 工程保护：持有 `ozid-admin` 的账号不能通过普通网页自助注销绕过“网页不可禁用平台管理员”的保护；先由受控 CLI 处理平台角色再进入普通自助流程，界面给明确说明，不暴露强制删除后门。

## 8. IP 白名单与入口防绕过

**来源 IP 白名单、身份认证、角色、认证时效和 CSRF 是叠加条件，互不替代。** 空列表默认拒绝，不能把空值解释为开放全部；首版不提供修改白名单的 Web 页面。

### 8.1 浏览器管理面

- 管理域名的页面/SPA fallback/资源及所有路径都经过网关 IP 防护，不能只限制首页或 `/admin` 前缀（独立控制台使用 `/users`、`/metro`）。
- BFF 对完整管理过程清单独立执行浏览器 IP 白名单：新用户管理全部读写、全部 `bff.metro.v1.AdminService` 方法、全部 `bff.v1.AccessTokenService` 方法，以及以后声明为管理过程的接口。只读豁免 CSRF不等于豁免 IP/角色。
- 管理浏览器接口还要求精确的控制台 Origin；不能因为 tripmap/metro 在公共 CORS 白名单内就允许其调用管理数据。缺失/伪造 Origin 不是认证手段，仍必须同时通过 Cookie、IP 和角色；非浏览器自动化走受控 MCP，而非绕过浏览器策略。
- 对 API 主机、旧产品反代、备用域名、其他 Host、原始服务端口的管理请求都执行同一规则；未知方法/路径保持拒绝，不落入透明转发。关闭或隔离会把 Cookie 留在错误 host 的旧代理登录入口。
- 跨域 OPTIONS 在允许来源/来源 IP 下可完成预检，实际 POST 再做全部校验；不允许用预检分支或路径编码逃过管理过程匹配。
- 公共账号操作和匿名产品接口不能被全局管理 IP 限制误伤；非白名单 IP 仍可使用 OzID 自助账号和普通产品功能。

### 8.2 客户端 IP 可信链

- 所有层按受信代理链解析真实对端，不信任公网请求自带的 `X-Real-IP`/`X-Forwarded-For`。网关覆盖客户端头，BFF 只在无法绕过受信网关的网络布局下读取约定头；直接访问 BFF 时使用 TCP 对端或拒绝该入口。
- 不允许通过用户输入 Host、Origin、请求体、转发头选择白名单。IPv4、IPv6、IPv4-mapped IPv6 与 CIDR 规范化一致；无效 CIDR、生产 `0.0.0.0/0` 或 `::/0` 配置在启动/部署校验失败。
- 网关与 BFF 白名单来自同一部署配置来源或有一致性校验；不把 BFF 设置为“信任任意转发来源”。具体允许 IP/CIDR 在部署时提供，不猜测、不沿用旧 Logto 白名单、不在规格中放真实名单。
- 本地开发可显式配置 loopback，不支持“开发参数缺失就自动放行全部”。更新 IP 后需要可验证的受控配置发布与回退，不通过网页改自己的来源策略。

### 8.3 MCP

- `POST /mcp/metro` 使用独立 `mcp_allowed_cidrs`（名称拟定），覆盖 initialize、tools/list、每次工具调用及批量、通知等请求；浏览器名单与机器名单可以不同，空机器名单只关闭 MCP，不误伤普通产品。
- 即使地址被允许，也只认 Bearer，忽略 Cookie，无浏览器 CORS 放行；仍执行 scope、到期/吊销、用户 active、认证版本和角色复核。
- 机器名单不能自动打开浏览器管理 RPC；浏览器名单也不自动开放 MCP。MCP 不套用浏览器密码重新认证，不接受普通 Cookie 作为备用鉴权。
- 改密、禁用、角色变更后已有 MCP 令牌失效的规则保持不变；白名单不能让旧令牌恢复。

## 9. 管理角色与用户管理

### 9.1 权限矩阵

| 操作 | 普通用户 | `ozid-admin` | `metro-admin` | 两角色 |
| --- | --- | --- | --- | --- |
| 管理本人账号 | 是 | 是（平台管理员注销受保护） | 是 | 是（同左） |
| 用户查询/账号安全审计 | 否 | 是 | 否 | 是 |
| 禁用/启用普通账号、网页授撤 `metro-admin` | 否 | 是，受下列限制 | 否 | 是，受同样限制 |
| metro 管理、目录审计与管理令牌 | 否 | 否 | 是 | 是 |
| 网页授撤 `ozid-admin`、禁用平台管理员、代注销/冒充/设密 | 否 | 否 | 否 | 否 |

平台角色只可通过受控 `usersrv-admin` CLI 初始化/授撤；不给首个注册者自动提权，不按配置邮箱自动授权。授撤平台角色与普通角色同样更新认证版本并审计；CLI 与 Web 复用业务规则，不建立两份角色真相。

### 9.2 用户查询与详情

- 只限 `ozid-admin`，返回 UUID、本人注册时验证的邮箱、昵称、账号状态、角色、创建时间等必要信息；邮箱是后台敏感数据，不复制给 `metro-admin` 或产品公开接口。
- 工程默认：支持规范邮箱精确查找、UUID 查找、状态/角色过滤、昵称字面搜索；分页默认 50、上限 100，使用稳定排序/游标，条件长度有限。不提供模糊邮箱枚举、批量导出、密码哈希、账号令牌、会话秘密、私有足迹/照片/骑行者资料。
- 账号已 deleting 时可显示只读状态，不能通过“启用”取消注销；待验证邮件挑战不冒充正式账号列入用户表。

### 9.3 状态与角色写入

- 网页操作只有禁用/启用和授撤 `metro-admin`，必须有原因（沿用 1–200 字符、拒绝控制字符和敏感内容的校验），明确展示目标与影响；不开放任意 role 字符串或整个角色数组替换。
- 浏览器请求含目标 UUID、期望的目标认证版本和幂等 mutation ID；操作者 UUID、真实密码认证时间从 BFF 的可信会话取，不能由请求体指定。
- 工程默认：收据按操作者＋mutation ID 唯一，24 小时保留，同 ID 同内容返回原结果，复用为不同操作拒绝；已生效重试不重复递增版本。目标版本冲突拒绝并要求刷新，不自动覆盖别的管理员/CLI 改动。
- usersrv 在同一事务中锁目标、检查其当前状态/角色、保护平台管理员、更新状态/角色和认证版本、写审计/收据；并发 CLI 授予平台角色不能与网页禁用穿透保护。
- 已确认禁止网页禁用平台管理员或授撤平台角色；工程默认进一步对任何持有 `ozid-admin` 的目标拒绝网页状态/角色写入，提示由受控运维流程处理。不能通过 UI 隐藏按钮代替服务端检查，也不能用普通账号方法代替管理权限。
- 禁用/启用、授撤角色的实际变化沿用递增 `auth_version`；启用或重新授权不复活旧会话/MCP 令牌，无变化的幂等操作不重复推进版本。

### 9.4 认证时效（工程默认沿用既有区分）

- 浏览器管理读和 metro 普通管理调用沿用 `admin_session_max_age`（当前默认 12 小时）的有效密码认证时间限制。
- 用户状态/角色写入必须在最近 15 分钟内真实验证密码，不能由页面传时间；创建管理令牌与本人注销仍沿用现有 15 分钟要求。
- 首版迁移 metro 的普通目录编辑、导入/导出、目录删除和令牌吊销不另加一套密码/原因字段，继续原有规则与二次确认；不要把账号管理新增的原因表单机械加入所有 metro 表单。若后续扩大高风险操作清单，先更新规格与测试。
- 用户中心的 `Reauthenticate` 为当前 BFF 会话更新真实认证时间；管理端过期时跳 OzID 的专用重新认证流程（可使用 `/security` 的受控模式）并安全返回，不能嵌入一套长期维护的密码框。对已失效/变更版本的会话要求重新登录，而不是重新认证旧身份。

## 10. 审计与接口增量

### 10.1 审计归属

- usersrv 保存账号安全与用户管理审计，metro 保留目录审计，BFF 继续拥有管理令牌创建/吊销记录；不为统一前端把业务库合并，也不伪造跨库原子事务。
- 账号状态/角色写入与账号安全审计同事务：操作者用户 UUID、目标 UUID、动作、原因、变更前后状态/角色、结果、请求 ID、时间。拒绝/无变化尝试有固定分类，不记录密码、邮件令牌、完整请求或任意数据库错误。
- 网页操作者身份必须来自已验证会话；不能直接接受现有 CLI 的自由文本 operator 为真实操作者。CLI 的标识及原因保留，前端区分 CLI/Web。
- 控制台将账号审计和 metro 审计分别提供过滤/分页，按对应角色访问；不在第一版做跨产品时间线聚合。管理令牌日志保持当前范围，不把“统一控制台”表述为已实现统一审计存储。
- 对用户列表/邮箱的读取记录操作者、过程、时间、请求 ID及结果，但不在访问日志/指标记录明文邮箱查询条件；审计权限不等于任意读取业务私有内容。

### 10.2 拟新增 interface

| 位置 | 拟新增能力 | 防护 |
| --- | --- | --- |
| `bff.v1` 共用导航 | `ResolveNavigation` 或同等小 interface | 匿名只读、服务端 registry、无登录授权能力；登记只读过程 |
| `bff.v1.AuthService` | `RevokeOtherSessions` | 有效会话、CSRF/Origin、只撤销本人其他会话，默认 10 次/15 分钟 |
| `bff.v1.UserAdminService` | `ListUsers`、`GetUser`、`SetUserDisabled`、`GrantMetroAdmin`、`RevokeMetroAdmin`、`ListSecurityAudit` | 全部浏览器管理 IP＋控制台 Origin＋`required_role=ozid-admin`，写操作另有 CSRF、近期认证、原因、版本与幂等 |
| `usersrv.v1` 内部管理契约 | 对应用户查询、状态、限定角色与审计查询 | BFF 内部签名、独立 `required_role`、目标保护和账号事务；仅此类跨用户管理方法可携带目标 UUID |
| 既有注册/重置契约与模型 | 绑定并返回安全导航上下文、统一邮件 origin | 所有 app/path 经服务端校验；用途、哈希、TTL、outbox 加密和不自动登录不变 |

方法名与 protobuf 拆分可在实现前按现有命名收敛，但不得靠通用管理代理暴露任意用户字段。用户管理新读接口默认每操作者 120 次/分钟、写接口 30 次/分钟；沿用 Redis fail-closed，错误不泄露底层数据。

BFF 不直写 usersrv 的 Ent 表；新内部方法有独立服务端角色检查。BFF 负责从会话提取并覆盖敏感上下文，usersrv 负责目标账号保护和业务约束。内部签名/传输失败仍是 internal/unavailable，不误报为“密码错误”。

## 11. 数据与兼容要求

- 扩展 usersrv 角色白名单加入 `ozid-admin`；扩展账号审计的真实操作者/渠道/前后状态及管理 mutation 收据；保留当前用户 UUID、密码哈希、状态/角色/认证版本及现有邮件任务，不重建或清空账号表。
- 若给注册/重置挑战增加导航上下文，应使用可空/有默认值的新增字段，旧挑战缺上下文时安全停留 OzID；不能把已有仍有效的链接解析成任意返回 URL。
- 自助“退出其他设备”可直接使用 BFF 当前会话表，不新增用户状态或改变认证版本；管理收据不存密码/完整邮箱。
- 不改变 tripmap/metro 的业务 schema、revision、媒体 key、公开主页 handle 或备份格式；本次只是入口和管理面迁移。若实现确实影响账号缓存字段，必须同次更新兼容和数据文档，不能按空缓存覆盖。
- 契约/Ent 只通过生成器更新，随代码提交迁移与 Go/TypeScript 生成物。新迁移以已有库为基线做增量；usersrv 第一版“不迁移旧 Logto 数据”不是删除现有 usersrv 数据的许可。
- 老产品 `/login`、`/account`、`/?signin=1` 和 `/admin/...` 可做明确的允许映射兼容跳转；不接受任意 `next`/URL，也不保留可继续输入密码或管理数据的另一套页面。已有邮件页只做覆盖 TTL 的受控过渡，之后退役。

## 12. 产品收敛与 metro 迁移

### trip-map

移除账号弹窗中的登录/注册/找回/资料/改密/设备/注销表单；保留同步状态、历史版本、导入本机足迹、媒体、分享、好友、通知等业务入口，增加“使用 OzID 登录”“管理 OzID 账号”。所有重新登录/错误页同样收敛，不能遗漏全屏无缓存失效页面。

未配置后端仍为本地模式，不渲染或请求 OzID。跳转之前按现有规则保存、导出与确认未同步内容；回来使用同一用户 UUID继续同步，换账号保留原用户缓存。

### metro

公开目录、城市/专题、`/me`、骑行者资料/乘坐记录继续由产品承载；账号设置跳 OzID，管理入口跳控制台对应分区。

把当前 `apps/metro/src/pages/admin/` 和只服务管理端的依赖迁入 `apps/admin`，替换 router/session/rpc 的应用适配，复用内部与浏览器契约。保持字段校验、引用删除限制、`expected_revision` 冲突、导入全有或全无/默认预览、目录版本、审计渠道和管理令牌只展示一次等既有规则。

旧 metro /admin 在过渡时只能安全跳到控制台，非白名单访问最终仍被拒绝；旧产品静态镜像不能作为继续开放管理 API 的理由。原管理 UI 测试随页面移动，产品套件改测跳转及普通功能回归，而不是删除管理测试。

## 14. 验收场景

### 域名、会话与导航

1. 使用两组完全不同的同站点测试域名构建/配置部署，无需修改业务源码，都能完成登录、邮件落地、业务返回、管理跳转；所有镜像 build args 和运行配置按文档真正生效。
2. HTTPS 下 OzID、控制台、两个产品直连同一 API origin。登录 Cookie 只属于 API 主机，含 HttpOnly/Secure/SameSite=Lax，无根域 Domain；业务及 OzID 的 localStorage/URL 无会话令牌。
3. 登录在 A 应用发起、OzID 完成，安全回到 A 原 pathname；B 应用通过 Me 观察到同一身份。独立同源代理不会被测试误算成共享成功。
4. 未允许的同站点兄弟子域、外站、null/伪造来源、协议相对/编码/反斜线/点段返回地址均不能获 CORS/导航放行；同站点 Cookie 附带不意味着通过 Origin/CSRF。
5. 直接访问 OzID 无来源时进入概览或登录；未知/退役来源不会开放重定向或把注册已成功误报为失败。已有会话的继续登录、显式换账号及无权限管理目标无循环跳转。
6. 注册/找回邮件只落 OzID；另一浏览器打开仍可完成账号流程并保留合法来源。fragment 清除、GET 不消费、刷新重新打开、注册/重置不自动登录及四邮件 adapter 规则不回退。
7. 更换 API 主机需重新登录；旧邮件域名过渡有 TTL 上限，关闭后有明确处理。新旧配置错配能被发布检查发现，不靠通配 CORS 修复。

### 用户端与数据保护

8. 两产品不再出现自己的密码、注册、找回、账号设置表单；所有失效入口都跳 OzID。产品 Origin 不能继续调用集中账号敏感写 RPC，正常 Me/业务请求/退出不被误伤；无后端的 trip-map 仍完整本地运行，不发账号请求。
9. 退出当前共享会话后各应用下次校验失效，其他浏览器仍有效；退出其他设备只撤销其他会话，重复操作幂等，不吊销 MCP、不误杀当前会话。
10. 改密/重置使全部旧浏览器会话及管理令牌在下次复核失败；网络/usersrv 故障显示可重试，不当成主动退出或清空缓存。
11. trip-map 带未同步修改离开并返回，队列/祖先副本/冲突/原 mutation ID 保留；切换 A/B 账号及迟到响应不交叉写入。浏览器存储失败阻止不安全跳转并能导出。
12. 用户在 OzID 注销，说明所有产品的数据范围并实际执行可恢复工作流；清理失败/刷新可重试，不能提前丢 Cookie。平台管理员自助注销受保护，其他用户、匿名本地数据不受影响。
13. 账号设备列表只展示实际有的数据；profile 不改邮箱、不覆盖 metro 骑行者资料。所有 OzID 页面在手机/桌面、键盘/密码管理器下可用。

### 管理 IP、权限与并发

14. IP 不在浏览器名单内时，控制台全部路径及 API 管理读写被拒；但公共登录、注册、账号设置及产品匿名/普通功能仍可用。名单空则管理面关闭，不自动允许全部。
15. 直连 API、旧域名/反代、裸端口、替代 Host、伪造 X-Real-IP/XFF、路径编码、OPTIONS 均不能绕过 IP 防护；受信多层代理、IPv4/IPv6/mapped 地址按预期匹配。
16. 浏览器名单、MCP 机器名单分别匹配，列入其中一个不能使用另一个入口；MCP 的 initialize/读工具/写工具/批量/通知均受限。允许 IP 下缺/错/过期/吊销的 Bearer 仍失败，Cookie 不作替代。
17. 普通用户、仅 ozid-admin、仅 metro-admin、双角色四种身份按矩阵验证 UI 和直接 API：不能因隐藏菜单、白名单命中或另一角色拥有而越权；内部用户管理与 metro 也独立 required_role 校验。
18. 浏览器管理 API 只接受控制台 Origin，产品公共 CORS 来源不能访问管理接口；读方法豁免 CSRF 不能跳过 IP/角色，所有写操作仍校验 CSRF。
19. 网页不能授撤 ozid-admin、状态/角色修改平台管理员、改他人密码、冒充或代注销。CLI 并发授予平台角色与网页禁用不能穿透目标保护；CLI 授撤后旧会话失效。
20. 用户状态/角色修改要求最近 15 分钟密码认证、原因、目标版本、mutation ID；旧版本或复用 ID 异内容拒绝，同内容响应丢失重试只生效一次；操作者/认证时间无法由浏览器伪造。
21. 超过管理认证期限转 OzID 重新认证后安全回来，但不自动重放旧写入；已失效版本不能通过重新认证升级。usersrv/Redis 不可用时不以旧角色或未核实来源放行，业务没有被调用；沿用既有 60 秒内部凭证及允许时钟偏差的在途窗口，不承诺撤回已开始的请求。
22. 用户查询分页与过滤上限生效、只在 ozid-admin 下显示邮箱；日志/指标无密码、令牌、明文邮箱查询和原始异常。状态/角色前后值与原因审计原子提交，拒绝尝试有分类。

### metro 回归与部署

23. 迁移后城市/线路/车型/专题 CRUD、字段级校验、引用限制、并发 revision 冲突、目录版本失效、导入预览/原子提交、导出再导入、审计和令牌页面功能全在；不是只放一个 iframe/旧站链接。
24. 管理令牌仍只展示一次、上限/到期/scope/吊销/认证版本约束不变，MCP 与网页共用业务规则；重新授予角色不恢复旧令牌。
25. metro 旧 /admin 只作安全跳转或退役，无可继续管理的旧 bundle/路由；公开目录、公开主页、/me 与乘坐记录回归无变化；没有 metro 上游时控制台不展示可操作的假分区。
