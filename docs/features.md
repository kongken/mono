# 功能描述

## 产品与使用流程

山海足迹帮助用户用颜色记录在中国走过的地方。用户在全国地图选择省级区域，进入省内地图，点击城市或区县即可自动配色并标记去过，再次点击取消；需要时另行编辑旅行记录：同一城市可以记录多次旅行，每次有自己的日期与备注（见“同一城市多次旅行（F5）”）。

当前数据覆盖 34 个省级区域和 497 个城市、自治州、县市或区县。本文中的“城市足迹”统称这些可记录区域；全国城市统计合并直辖市及港澳的区县后，共 391 个统计目的地。数据范围见 [数据与地图说明](data-and-maps.md)。

## 全国与省内地图

- 海南省内主图聚焦海南本岛，三沙使用独立岛屿附图，整个附图可点选，两个视图保留同一套区域 ID 和标记规则；本岛的黎族及黎族苗族自治县地图标签使用简称，列表仍显示完整名称。开启 OSM 后初始视野同样聚焦海南本岛，可拖动至远海岛屿。
- 初始打开全国地图；点击地图轮廓或目的地列表进入对应省内地图。
- 全国地图下方提供北京、天津、香港、澳门“快速进入”按钮，解决小区域轮廓难以点选的问题；按钮显示与全国地图一致的探索颜色，点击或键盘 Enter / 空格进入对应区域，点击入口本身不会标记足迹。按钮高度至少 44px，窄屏采用两列布局，不受地图缩放影响。
- 普通省份展示城市、自治州等下一级区域，直辖市及港澳展示区县，台湾展示县市。金门县及连江县（马祖）在福建展示和记录；福建共 11 个可记录区域，台湾共 20 个。
- 全国地图中，存在省份独立标记或任意城市足迹的省级区域都会着色。
- 全国地图右上角提供“按省份 / 按城市”着色切换，默认按省份。选择“按城市”后，首次会加载全部 34 个省份的本地城市边界（约 4 MB，之后不再重复请求），每个城市、自治州、县市或区县单独按其足迹颜色填充，未去过的显示灰色；仅有独立省份标记而无城市足迹的省份，其全部区域显示为该标记颜色的浅色。省份边界以细线叠加，省份名称与快速进入按钮保持不变。该模式下点击任意城市或按 Enter / 空格聚焦省份轮廓，均进入所在省份的省内地图，不在全国地图直接标记；悬停提示显示“城市 · 省份”及是否去过。加载失败时提供重新加载按钮。切换方式仅在当前页面有效，不持久化，进入省内地图再返回仍保持所选方式；全国分享图片与当前着色方式一致。
- 省内地图只按城市足迹着色；单独标记省份不会把省内全部城市标为去过。
- 全国地图、全国目的地列表与全国分享图片统一自动配色：根据本地全国地图的共同边界，预先为全部 34 个省份分配绿、黄、橙、蓝、紫；有共同边界的省份使用不同颜色，无共同边界的省份可以复用颜色，在满足相邻不同色的前提下尽量均衡使用五色。显示颜色独立于保存的城市及省份标记颜色，旧备份导入后同样生效，不修改已有记录。编辑城市、调整记录顺序、导入、新增或移除已探索省份均不会改变其他省份的颜色；未探索省份仍显示灰色。
- 点击省内区域或城市列表主按钮直接切换去过状态，不弹出编辑窗口；键盘 Enter 或空格执行相同切换。
- 已去过的城市列表行显示铅笔编辑入口，打开弹窗回填原记录。
- “中国”面包屑、返回按钮或品牌入口可回到全国地图。切换地图会清空搜索、重置缩放并回到地图标签页。
- 地图支持放大、缩小和重置；当前为以中心缩放，不支持拖动平移。地图加载失败时提供重新加载按钮。
- 省内地图右上角提供“OSM 底图”开关，默认关闭。开启后该省改用 OpenStreetMap 瓦片底图，行政区域叠加在底图上，支持滚轮或按钮缩放、拖动平移，以及“回到全省视图”按钮；底图经过淡化处理以突出区域颜色和名称，左上角仅保留返回按钮与标题；点击、键盘 Enter 或空格切换去过状态的规则不变。开关偏好保存在当前浏览器，全国与省内地图共用同一个开关，默认关闭。
- 全国地图同样提供“OSM 底图”开关（与“按省份 / 按城市”并排，手机上上下排列）。开启后全国地图改用 OpenStreetMap 瓦片，省份（或城市）边界与着色叠加在底图上，支持滚轮或按钮缩放、拖动平移，“回到全国视图”按钮回到主体国土视野（不含远海岛屿，可拖动至南海）。点击省份或城市进入省内地图，规则与本地绘制一致；两种着色方式都只标注省份简称，不标注城市名，按城市着色时悬停显示“城市 · 省份”。按城市着色下 497 个城市可点击，键盘 Tab 聚焦的是 34 个省份轮廓，Enter / 空格进入省内地图。关闭开关后回到本地 SVG 全国地图（含南海附图）。
- 开启底图后浏览器会向 `tile.openstreetmap.org` 请求瓦片，页面角落显示 OpenStreetMap 署名；底图加载失败时提示可关闭底图，区域标记仍可使用。关闭开关即恢复原有 SVG 地图和中心缩放。

## 省份独立标记

省内页面提供“标记去过此省”和“取消省份标记”。新增独立标记保存的颜色优先沿用该省已有独立标记或第一条城市足迹的颜色；尚未探索的省份自动选择全国已探索省份的记录代表色中使用次数最少的颜色，同次数时按调色板顺序选择，适用于只想记录去过该省、尚未补全城市的情况。

独立标记与城市足迹相互独立：取消独立标记会保留城市记录；如果仍有城市足迹，全国地图中的该省仍算已探索。

## 城市足迹

地图和目的地列表支持一键标记与取消。本省第一条城市足迹沿用该省独立标记颜色；没有独立标记时，自动选择全国已探索省份的记录代表色中使用次数最少的颜色。后续新增足迹自动使用本省现有足迹中使用次数最少的颜色，并默认当天日期和空备注；使用次数相同时按调色板顺序选择，已有城市的颜色保持不变。

取消城市打卡会移除该城市的足迹及其全部旅行记录（日期与备注）；城市有两次及以上旅行时，先弹出确认窗口说明将删除的旅行次数。提示出现期间可点“撤销”恢复完整城市与每次旅行，旅行 ID 不变。撤销入口仅针对最近一次取消，其他操作提示或提示自动消失后不可用。照片与附件不随取消删除（见 F4）。

可从已标记城市旁的铅笔按钮、“添加足迹”、收藏卡片或最近足迹进入编辑弹窗。

| 字段 | 当前规则 |
| --- | --- |
| 省份 | 可从全部省级区域中选择；改变省份会清空城市和旅行草稿，重置颜色 |
| 城市 / 区县 | 必须选择，候选项随省份变化；选择已有足迹的城市会载入它的颜色和全部旅行 |
| 颜色 | 默认自动选择山野绿、日落黄、珊瑚橙、海岸蓝或暮光紫，可手动调整；颜色属于城市，不属于单次旅行 |
| 旅行记录 | 每次旅行一张卡片，含日期与备注；可“添加另一次旅行”或删除某一次。新增城市默认带一次旅行（日期为当前浏览器本地日期），可删除成零次 |
| 旅行日期 | 可留空；填写时必须是真实存在的日历日期 |
| 旅行记忆 | 选填，最多 1000 个 UTF-16 码元（浏览器 `length`），保存时只修剪被编辑过的备注的首尾空白，未改动的备注原样保留 |

每个区域 ID 只保存一条城市足迹，同一城市的多次旅行是它的子记录（见下节）。再次保存已有城市会更新原记录，不会增加城市数量。

已有足迹可通过“取消城市打卡”删除。删除后，该城市恢复未探索状态，其旅行记录一并删除，收藏和统计同步变化；若该省没有其他城市足迹和独立标记，全国地图中的省份也恢复未探索。

## 同一城市多次旅行（F5）

当前已实现。一座城市可以有任意多次旅行；每次旅行是独立子记录：

- 每次旅行有稳定的 ID（`t` 加时间与随机字符，匹配 `^[A-Za-z0-9_-]{1,64}$`）、日期（可空）、备注，以及独立的修改时间；不同设备修改同一城市的不同旅行不会冲突。
- 城市颜色规则不变，仍按本省已有城市足迹的颜色使用次数自动选择；第二次旅行不改变城市颜色，也不改变全国、省内及统计中的已打卡城市数，两次旅行的城市只计 1 座。统计新增“旅行次数”（首页统计条与统计弹窗），等于全部城市的旅行总数。
- 删除最后一次旅行时，城市打卡保留（零次旅行的城市在列表中显示“暂无旅行记录”）；取消城市打卡才会删除城市及其全部旅行。
- “旅行足迹”列表与“最近足迹”按每个城市最近一次有效旅行日期降序排列，没有日期的城市排在有日期的之后，同日期按区域 ID 稳定排序；卡片显示最近一次旅行的备注、日期，旅行两次及以上时显示“共 N 次旅行”。
- 旧数据兼容：本地、备份、账号缓存和云端中的版本 1 数据（每城市一个日期与备注）转为每城市一次旅行，ID 固定为 `legacy-<区域 ID>`，日期、备注（含空记录）原样迁入；前端与服务端使用同一 ID，因此多设备分别升级同一条记录会合并而不是重复。
- 版本 1 数据里不是真实日历日期的日期（如 2 月 30 日）不会被静默清除或改写备注：本地读取按 F0 保护流程提供“清除 N 个不存在的日期并恢复”（只清日期，备注与其余日期保留，原始数据先另存副本）；导入文件时先提示并要求点击“清除不存在的日期并导入”。
- 编辑窗口的每张旅行卡片在登录且该旅行已同步后提供“这次旅行的照片与附件”；城市级“照片与附件”仍列出该城市全部文件。媒体与旅行是可选关联：关联的旅行被删除后文件保留，仍可在城市附件中查看和单独删除，标注“关联的旅行已删除”。媒体不会关联到他人或其他城市的旅行。F4 的类型、大小和每城市 20 个的限制不变。
- 取消城市打卡、删除某次旅行都不删除媒体。
- 媒体窗口里的“关联旅行”选项和卡片标签形如“第 N 次 · 2026-03-01 · 备注前 12 个字”或“第 N 次 · 日期未记录”（序号取自城市内的显示顺序），同一天或没有日期的旅行也能区分；已删除旅行的文件显示“关联的旅行已删除”。
- 从编辑窗口点“这次旅行的照片与附件”或城市级“照片与附件”时，编辑窗口暂时收起、**未保存的草稿原样保留**；关闭媒体窗口（按钮或 Esc）回到同一个编辑窗口，日期与备注仍是编辑中的内容，焦点回到刚才点击的按钮。草稿没有改动时回来会重新载入最新的城市数据。这些按钮的无障碍名称是“这次旅行的照片与附件（第 N 次）”，包含可见文字。
- **保存时合并，不覆盖。** 编辑窗口记住打开时的城市，保存时只把你自己的改动（相对打开时的差异）应用到保存瞬间的最新城市上：编辑期间别处新增、修改或同步来的旅行都会保留。同一次旅行两边都改过（含一方删除）、颜色两边改成不同值、或城市被取消而草稿仍有改动时，弹出“编辑期间这条记录有了新的变化”，逐条选择“用我的”或“保留最新”，可“返回编辑”。选择期间同一条记录又有了新的变化时，窗口按最新内容重新显示并提示，变化过的记录需要重新选择，不会把旧的选择应用到没看过的新内容；无关的新旅行自动保留，不需要选择。
- **取消与撤销使用当时的城市。** 确认窗口显示的是此刻的旅行数；在确认窗口打开期间到达的新旅行也随城市一起删除，“撤销”恢复删除瞬间的整座城市（含这些旅行，ID 不变）；若撤销前同一城市已被重新添加，被删除的旅行并回现有城市而不是覆盖。

**账号与版本兼容。** 新前端对每个足迹与快照请求带 `X-Tripmap-Schema: 2`，并在首次同步前通过状态接口确认后端支持旅行（`footprint_schema ≥ 2`）。后端未升级、返回旧格式时前端暂停同步，显示“云端服务尚未升级到支持“同城多次旅行”的版本……”，编辑保留在本机，不会向旧后端发送会丢失旅行的写入；这依赖前端自检，不依赖部署顺序。账号第一次被新前端写入时在服务端升级到结构 2；此后没有该请求头的旧客户端读写会得到“client upgrade required”提示，而不是看不到或覆盖新旅行。旧前端的批量同步缓存里未发送的批次升级时原样保留（改为兼容的旧版操作），按原请求 ID 重放：服务端已生效则返回原结果，没有生效则按本机编辑重新计算差异。

**限制。** 账号升级为单向；回退到旧后端需要数据库备份（见 [后端初始化](backend.md)）。旅行没有单独的撤销入口（取消城市打卡有）；城市不能在旅行之间移动，一次旅行永远属于创建它的城市。旅行 ID 在同一账号内全局唯一：迁移时本机旅行 ID 若已被云端另一座城市的旅行占用，会改用新 ID（见“本地足迹迁移”），内容不变。

**旧版页面共存。** 旧版页面（F5 之前打开着的标签页）仍写 `shanhai-travel-v1` 和 `shanhai-cloud-v1:<用户 ID>`。新版把数据存放在独立的 `shanhai-travel-v2` 与 `shanhai-cloud-v2:<用户 ID>`，旧键只读、**从不被新版改写或删除**（退出登录、注销的规则见下）：旧页面事后写入旧键不会覆盖新版数据，新版未同步的编辑（含队列里的原请求 ID）关闭页面后仍然完好。新版第一次启动时若只有旧键，读取旧键并在首次编辑时写入新键，旧键原文保持不变。旧页面在新版接管之后写入旧键的内容会在新版打开时提示“旧版页面修改了本机足迹/账号缓存”，可“导出旧版页面数据”、“不合并，保留在旧位置”（旧键仍保留，之后不再提示同一份内容），或“合并新增内容”（只新增新版没有的记录，不删除任何内容，两边都有但不同的保留新版内容）；账号缓存同理。

### F5 验收

### F5 验收

1. 在杭州记录两次旅行：已打卡城市和城市颜色不变，旅行次数为 2，列表卡片显示“共 2 次旅行”及最近日期与备注；手机无横向溢出。
2. 删除其中一次旅行，另一次与城市保留；再删除最后一次，杭州仍是已打卡城市，卡片显示“暂无旅行记录”。
3. 取消有两次旅行的城市时先弹出确认；确认后城市与旅行消失，“撤销”恢复同样的两次旅行（ID 不变）。
4. 浏览器里是版本 1 的本地数据（`shanhai-travel-v1`）：打开页面时没有任何写入，首次编辑后版本 2 数据写入 `shanhai-travel-v2`，旧键原文不变，日期与备注进入 `legacy-<区域 ID>` 旅行。此后旧页面改写旧键，新版刷新后数据不变并提示“旧版页面修改了本机足迹”，可合并、导出或保留在旧位置。
5. 导入版本 1 备份，导出为版本 2 后再次导入，内容一致；备份含不存在的日期时必须点击“清除不存在的日期并导入”，备注保留。
6. 登录后保存两次旅行：服务端出现 1 个城市和 2 次旅行；离线或响应丢失后刷新，修改只写入一次。
7. 一台设备取消城市、另一台为它新增旅行：出现冲突弹窗，选“以本机为准”后城市与旅行全部回来；两台设备改同一城市不同旅行时自动合并。
8. 后端未升级时显示中文提示，不发送任何写入；旧客户端（无请求头）访问已升级账号被拒绝。
9. 迁移预览、快照列表与恢复预览都显示旅行数量，恢复后已删除的旅行回来。
10. 旅行关联的照片：上传到某次旅行后，删除这次旅行与取消城市都不删除文件，文件仍在城市附件中，标注“关联的旅行已删除”。同一天或无日期的旅行在“关联旅行”选项里显示不同的文字。
11. 编辑窗口里改了备注但未保存，点这次旅行的照片：媒体窗口打开，关闭（含 Esc）后回到编辑窗口，改动仍在，焦点在刚才的按钮上；保存后云端是改后的备注。
12. 编辑窗口打开期间另一设备新增了旅行：保存后新增的旅行仍在；另一设备改了同一次旅行时出现冲突选择，选择期间又改一次则窗口刷新内容并要求重新选择。
13. 取消确认窗口打开期间到达了新旅行：确认后它随城市删除，撤销后连同它恢复。
14. 键盘：在空白状态聚焦“添加足迹”按 Enter 打开编辑窗口且焦点在窗口内，Esc 后焦点回到“添加足迹”；从城市卡片打开编辑窗口后取消该城市，焦点落到“添加足迹”；取消确认和编辑冲突窗口关闭后焦点回到编辑窗口里发起它的按钮。在编辑窗口之上的取消确认、编辑冲突（及媒体）窗口，Esc、关闭按钮或点击窗口外都只关闭这一层，编辑窗口和未保存的草稿保留，再按一次 Esc 才关闭编辑窗口；即使 Esc 在确认窗刚获得焦点的瞬间按下也是如此。320 × 640 以及 200% 缩放下（约 640 / 320 CSS 像素宽）页面和编辑窗口没有横向滚动，“保存足迹”滚动可达。首页统计在宽度不超过 420 像素时排成 2 × 2，四项内容完整显示。
15. 迁移：本机数据需要超过 2000 项变更时，预览阻止确认并说明原因，不做快照也不发送；本机旅行 ID 与云端另一城市的旅行重复时，预览提示改用新 ID，上传后双方都保留。迁移已被接受后断网刷新、再离线编辑使总量超过 2000 项时，**所有已接受的内容和原子意图都保留在本机**，同步暂停并提示导出或减少内容，不发送任何一部分；减少到一批以内后整体发送一次。

## 搜索与足迹查看

- 目的地侧栏提供“目的地 / 旅行记忆”两种搜索范围，两者不混用；搜索不会自动标记或改写足迹。
- **目的地搜索（F9）：** 全国匹配省份全称、简称及省内城市/区县名称，展示所属省份（例如“杭州 / hangzhou / hz”指向浙江，“jinmen”指向福建）；省内只匹配本省区域。手机“选择城市”使用同一套规则。
- 支持名称片段、无声调拼音、拼音首字母（含部分匹配）；拼音忽略大小写、全半角、声调、空格和撇号，`ü` 可写成 `v`。直接匹配优先，只有当前范围完全无直接匹配时，才尝试一次增字、漏字、替换或相邻字换位纠错：中文至少 2 字，英文至少 4 字母（例如 `hangzou`、`hangzohu`）；不对短首字母模糊纠错，不承诺任意简称或多处错字都能匹配。搜索索引随项目分发，完全离线可用。
- **旅行记忆搜索（F9）：** 检索每次旅行的完整备注（包括不是最近一次的记录），只搜索自己的数据；全国范围搜全部，省内只搜本省。关键词按空白分隔，所有关键词须在同一条备注中出现，英文不区分大小写；中文按字面片段匹配，无需分词。`%`、`_`、引号和 HTML 标签都是普通文字，不执行 SQL、正则或 HTML。空查询不展示全部私密记录，最多 100 个 UTF-16 码元、8 个关键词。
- 未登录、离线或有未同步修改时检索当前本机足迹/账号缓存（包含未同步修改）；已登录且同步完成时，300ms 防抖请求 `SearchService.SearchNotes`，每页 20 条、支持“加载更多记忆”。结果按日期降序，无日期在后，同日期按区域 ID、旅行 ID 排序；分页绑定足迹 revision，版本变化或请求失败时回退本机缓存并明确提示，可重试云端检索。更改查询/省份、退出或切换账号时废弃旧请求与结果，不持久化查询、结果或私密备注索引。
- 每条结果显示城市、日期、含关键词的纯文本摘要和记录标识；点击打开城市编辑窗口并聚焦、滚动到命中的那次旅行。搜索可清空，没有匹配结果时显示提示。
- “旅行足迹”标签页展示城市足迹卡片，按每个城市最近一次有效旅行日期降序排列（无日期的城市在后，同日期按区域 ID 排序）。当前选中省份时，只展示该省足迹。
- “查看全部”清除省份筛选并切换到收藏视图。
- 最近足迹按同一规则（每个城市取最近一次有效旅行日期）展示前 4 座城市；没有日期的排在有日期之后，城市显示旅行次数。点击卡片可以编辑。
- 尚无足迹时提供空状态及添加第一站入口。

## 统计口径

| 指标 | 计算方式 |
| --- | --- |
| 已探索省份 | 省份独立标记的 ID 与城市足迹所属省份 ID 的去重并集 |
| 已打卡城市 | 全国按目的地去重：北京、天津、上海、重庆、香港、澳门各自有任一区县足迹即计 1 座，其余区域按区域 ID 计数；不包含独立省份标记 |
| 全国城市打卡率 | 上述去重城市数量 / 同口径目的地总数（当前 391），保留一位小数 |
| 中国探索度 | 已探索省份数量 / 34，四舍五入为整数百分比 |
| 旅行次数 | 全部城市足迹下的旅行记录总数；同一城市多次旅行只增加它，不增加已打卡城市和省份数 |
| 省内已走过数量与打卡率 | 当前省份城市足迹数量 / 该省可记录区域总数；百分比保留一位小数 |

## 足迹统计、年度报告与成就（F8）

- “足迹统计 / 生成图片”入口打开统计弹窗，顶部固定展示全国已探索省份数量与比例（分母 34）、全国城市打卡数量与比例（分母 391）、旅行总次数，并提供 **“总览与分享图”**、**“年度报告”**、**“旅行成就”** 三个标签页。
- **统计口径一致性：** 全国城市包含地图中的自治州、县市等目的地，北京（`110000`）、天津（`120000`）、上海（`310000`）、重庆（`500000`）、香港（`810000`）、澳门（`820000`）6 个直辖市及特区的区县各自合并最多计 1 座城市，分子和分母使用相同合并口径；省内进度、省内分享图片及首次解锁区域明细仍按实际可记录城市或区县（共 497 个）统计。独立省份标记只影响已探索省份统计，不增加城市数量。前后端通过共享测试夹具（`packages/fixtures/report-stats.json`）保持计算结果完全一致。
- **总览与分享图片：**
  - 预览当前全国或省内地图的分享卡片；全国卡片展示全国城市数量与打卡率，省内卡片展示该省数量与打卡率，两者均展示全国已探索省份数量。
  - “生成并下载 PNG 图片”在浏览器内生成 1800 × 2000 的图片，包含本地行政区域地图、标记颜色、统计和生成日期；不包含旅行备注和 OSM 瓦片，不受地图缩放或搜索影响，无需第三方服务。生成后提供图片链接，手机可打开后长按保存；生成失败显示重试提示。没有足迹也可生成空地图，地图未加载成功时下载按钮禁用。图片用于分享，不替代 JSON 备份，无法通过图片恢复足迹。

- **年度报告（按用户时区汇总与可追溯）：**
  - **时区与年份归属：** 支持按用户本地 IANA 时区（默认当前设备时区，可切换 `Asia/Shanghai`、`UTC`、`America/New_York` 等；无效时回退 `Asia/Shanghai`）确定当前本地日期（`generated_on`）与当前年份（`current_year`）。旅行记录的日期是 `YYYY-MM-DD` 日历日期，按其年份归入对应年度；未填写日期的旅行计入总览的“未填日期旅行数”，不强行归入某一年。默认选中最近一个有旅行记录的年份（无有日期旅行时选中当前年份），可切换查看任意年份。
  - **年度指标：**
    - 当年旅行次数、跨越天数（当年最早至最晚旅行日期的含首尾日历跨度）及最活跃月份；
    - 当年走过城市数（全国 391 城市合并口径）与实际涉及区域数；
    - 当年新增城市数（全国口径下首次有日期旅行落在该年的目的地数）与首次解锁区域数（如 2025 年已去过北京东城区，2026 年首次去西城区时，2026 年首次解锁区域计 1 个，全国口径新增城市计 0 座）；
    - 当年跨越省份数与首次探索省份数。
  - **年度代表记录与完整时间线追溯：** 展示年度首站与末站、最长旅行记忆（按备注 UTF-16 字数最长，同长度取日期最新）、年度常去目的地（当年旅行次数最多的区域）、当年首次解锁区域列表、当年跨越省份列表以及按日期升序排列的当年全部旅行时间线；每项代表记录、区域和旅行条目均可点击直接打开对应城市的足迹编辑窗口。

## 保存与备份

每次足迹或独立省份标记变化后自动保存到当前浏览器。刷新或重新打开同一网站来源后恢复记录；页面选中的省份、搜索和缩放不会持久化。

当前结构为版本 2（城市足迹含旅行子记录），读取时同时接受版本 1 与 2；版本 1 在内存中转为版本 2，导出一律是版本 2。版本 2 存放在 `shanhai-travel-v2`；`shanhai-travel-v1` 是旧版页面的键，新版只读取、从不写入或删除它（无需再复制“迁移前备份”：原文一直留在旧键里）。本地存储只在用户编辑、导入或处理保护窗口后才写入，仅打开页面不会改写任何键。每次写入前检查 `shanhai-travel-v2` 的文本仍与本页上次读取或写入的一致；首次从旧键升级时，先记录旧键当时的内容摘要，记录失败则拒绝保存并提示导出。另一个页面修改了本机足迹时，本页暂停保存并弹出窗口，提供“导出本页数据”“导出另一个页面的数据”“载入另一个页面的数据”“用本页数据覆盖（保留对方副本）”。覆盖会先把**对方页面的原文**另存为 `shanhai-travel-v2-conflict-<时间戳>`；浏览器拒绝保存时，必须先点击“导出另一个页面的数据”，并且导出的正是即将被替换的那一份：导出后对方页面又写入了新内容，需要重新导出新内容才能覆盖。导出本页数据不能代替备份对方数据。

旧缓存、账号缓存及备份中，金门县或连江县（马祖）仍归台湾的记录会在读取时自动改归福建，保留区域 ID、颜色、日期和备注；独立台湾省份标记保持不变。仅这两类已知旧记录适用迁移，其余无效记录仍触发校验保护。

导出会下载带有日期的 JSON 备份。导入最多 32 MB，会校验文件并显示城市与旅行数量，用户确认后替换当前全部足迹和独立省份标记；确认前可导出当前数据。无效文件只显示错误提示，不替换记录。文件限制、格式及兼容性见 [数据与地图说明](data-and-maps.md)。

保存失败时显示提示与导出入口。数据暂不跨浏览器或设备同步，清除网站存储会移除本地记录。

### 本地数据读取失败保护（F0）

启动时本地缓存存在但无法读取（JSON 损坏或被截断、结构版本不是 1 或 2、记录未通过校验、日期不是真实日历日期）时，页面不会回落为空数据并保存，而是：

- 弹出不可关闭的“本地足迹数据无法读取”窗口，说明原因，并暂停自动保存；浏览器中的原始缓存保持不变。
- “导出原始数据”下载原始字符串（`山海足迹-原始数据-日期.json`），可多次导出。
- “恢复可识别的记录”仅在内容是版本 1 或 2、至少有一条有效记录且没有不存在的日期时出现，显示可识别及将丢弃的足迹、旅行、省份标记数量；确认后只保留通过校验的记录（重复城市保留第一条）。
- 内容含不是真实日历日期的旅行日期（如 2 月 30 日）时，不会自动清除：出现“清除 N 个不存在的日期并恢复”，只清空这些日期，备注和其余内容原样保留，无法识别的记录按提示丢弃；原始数据先另存副本。
- “以空数据开始”需再次点击确认；确认后以空数据继续。
- 恢复或以空数据开始前，原始数据会复制到浏览器中以其来源键命名的 `<来源键>-unreadable-<时间戳>`（如 `shanhai-travel-v2-unreadable-…` 或 `shanhai-travel-v1-unreadable-…`）；若浏览器拒绝写入（如空间已满），需先导出原始数据才能继续。旧键里无法读取的内容永远不会被新版覆盖，只能导出。恢复预览的“将丢弃的旅行”数量包含因整条城市记录无效而丢弃的城市里的旅行（版本 1 的城市计 1 次）。
- 缓存不存在或为空字符串属于正常的首次使用，不触发该保护；浏览器禁用存储时仍按保存失败提示处理。

## 账号与云端同步

仅当构建时设置了 `VITE_API_BASE_URL`（见 [后端初始化](backend.md)）才出现，未设置时界面没有任何登录入口，应用保持纯本地模式。登录可选，不登录的行为完全不变。

**登录与注册。** 页眉“登录”按钮（手机上为圆形图标）打开登录弹窗：用户名 + 密码登录，或切换到“注册”创建账号（用户名 3–32 位小写字母、数字、下划线，密码至少 8 位，昵称选填）。**已实现（#30–#33）：** 密码与 OAuth 注册/登录经 BFF `bff.v1.AuthService`，会话为 HttpOnly Cookie `shanhai_sid`（`SameSite=Lax`），写操作带 CSRF；`localStorage` 的 `shanhai-session-v1` 只存用户信息与可选过期提示，**不存** Bearer/会话令牌；账号弹窗的已登录设备列表与撤销其他设备经 BFF `ListSessions` / `RevokeSession`（BFF 存储，标记当前设备）；城市足迹与省份标记的读、增量与批量同步经 BFF `bff.v1.FootprintService`（含 `GetFootprints`、`GetChanges`、`SyncChanges` 及仍被调用的单条写操作），经内部 gRPC 到 tripmap，保留 revision/幂等/2000 项批次语义。**已实现（#42）：** 提醒与通知设置经 BFF `bff.v1.NotificationService`；邮件退订链接仍打开 `/api/notifications/unsubscribe`（BFF 公开 HTTP，不经 CSRF）。**待迁移（#34–#44）：** 快照、媒体、协作等仍走透明网关 `tripmap.v1` + Bearer。BFF `config.bff.yaml` 配置了 GitHub、Google 或 Logto 时，弹窗下方显示对应按钮（Logto 使用服务端配置的显示名，默认“Logto”），点击后跳转第三方授权，回到 `/auth/callback/<provider>` 后完成登录。回调时必须与本浏览器发起的授权（保存在 `sessionStorage` 的 provider 与 state）一致，且只能使用一次，否则提示“登录请求无效或已过期”；回调地址里的授权码在请求前就从地址栏移除。Logto 使用 OIDC 授权码 + PKCE：授权地址带 `code_challenge` 与 `code_challenge_method=S256`，换取令牌所需的 `code_verifier` 只保存在服务端；登录后创建或进入 `(logto, sub)` 账号，足迹同步、好友邀请码、会话管理和注销（需 15 分钟内登录）与其他第三方账号一致，不与 GitHub/Google 账号按邮箱合并。当前不提供仅第三方登录的界面开关，用户名密码登录始终并列显示；真实 Logto 授权验收留待部署后进行。错误提示一律为中文。

**登录后的数据。** 登录后页面显示并编辑该账号的云端足迹，本机登录前保存的本地足迹不直接显示，也不会自动上传，需通过下文“本地足迹迁移”主动导入。每次编辑先把目标数据及服务端确认的祖先副本一起保存到本机账号缓存，再立即显示并后台按最多 2000 项的批次发送（更大的普通改动按序拆成多个批次，城市先于其旅行；迁移是整体提交，规则见下）；本机写入失败时拒绝此次编辑并提示导出备份。全部发送成功后显示“已同步到云端”，发送失败不回滚或丢弃修改，显示“本机已保存，待同步”。页面重新可见、网络恢复或点击重试时自动尝试同步。

**并发冲突。** 初次登录读取云端快照，随后读取带删除标记的有序增量；历史不足时重新取完整快照。同步，将本机尚未同步的差异与其他设备修改做三方合并；不同城市、同一城市的不同旅行或省份标记自动合并，同一条记录双方改成相同内容也自动合并。同一记录不同修改（含一方删除，包括一方取消城市、另一方新增或修改其旅行）暂停写入，弹窗列出冲突区域，用户选择所有冲突记录“以本机为准”或“以云端为准”，不影响其他记录；可先导出本机足迹。每批写入携带精确 revision（包括 0）与持久化请求 ID；丢失响应后重放同一请求，不重复提交或反转标记；并发版本变化时重新读取并检查，连续竞争最多自动重试三次，之后保留修改供手动重试。旅行日期不用于判断修改先后。

**启动与离线。** 恢复登录时先用本机缓存的云端副本显示，同时向云端拉取；没有缓存则显示“正在加载云端足迹…”。有可校验的账号缓存时，即使离线仍可标记、编辑、删除、撤销和导出；未同步修改跨刷新保留，联网后重试同步。没有缓存且拉取失败时显示全屏错误，不接受编辑。账号缓存无法解析或校验失败时保留原始字符串并阻止读写覆盖，提供“导出原始账号缓存并退出”；下载触发后退出会明确清除该账号缓存。浏览器拒绝保存时暂停编辑，当前内存足迹仍可导出。

**本地足迹迁移。** 登录后，若云端数据已确认（本次会话已完成同步、无待发送修改、无冲突）、本机本地足迹可读取、有记录且尚未对该账号迁移过，自动弹出“把本机足迹迁移到云端”窗口；若迁移不会产生任何变化（本机记录云端都已有且相同），不弹窗，直接记为已处理。账号弹窗在有本机足迹时始终提供“导入本机足迹”按钮，同样要求云端已确认。本地足迹读取失败（F0 的保护状态）时不提供迁移，提示退出登录后在本地模式处理。

预览显示“新增到云端 / 新增旅行记录 / 用本机覆盖 / 保留云端 / 无需变动”的数量：只在本机有的城市（连同其旅行）、已有城市下只在本机有的旅行和省份标记会新增；只在云端有的永远保留，迁移不删除云端任何记录；两边都有且内容不同（城市颜色不同、同一 ID 旅行的日期或备注不同，或省份标记颜色不同）列为冲突，城市与旅行分别逐条选择；两边日期与备注完全相同、ID 不同的旅行视为同一次旅行，不重复新增，逐条选择“用云端”（默认）或“用本机”，并有“全部用云端 / 全部用本机”。旅行日期不是修改时间，不用于自动判断谁更新。预览可导出云端备份；打开弹窗时预览即固定，不随后台同步变化。

迁移前备份：云端已有足迹时，点“确认迁移”会先在云端保存一份“迁移前自动保存”的快照（见下文“云端备份与历史版本”）；快照保存失败则提示并不开始迁移，云端与本机都不变。云端为空时不需要快照。

迁移是整体提交，必须在**一个**原子批次里完成（最多 2000 项，可容纳全部 497 个城市、数百次旅行和 34 个省份标记），不会拆成多批：需要的变更超过 2000 项时，预览直接提示并禁用“确认迁移”，此时不做快照、不发送，本机和云端都不变，请先导出备份并缩减。本机旅行 ID 若已被云端另一座城市的旅行占用（旅行 ID 在账号内唯一），上传时改用新的 ID（原 ID 截断后加 `-m-<区域 ID>`，必要时加序号），内容不变，预览会提示数量。确认后，目标数据和“这是整体提交”的意图一起写入本机账号缓存（`atomic`），再发送；失败或断网时全部保留在本机，刷新后仍记得这是整体提交，联网后用同一请求 ID 重放，不会重复写入也不会出现部分结果；窗口显示“正在迁移”直到服务器确认，确认后清除该意图。若在迁移被接受之后、批次发出之前又有离线编辑或重新基于云端使总量超过 2000 项（或连接不支持批量请求），**不会拆分、也不会回退任何已接受的内容**：同步暂停，提示“未同步的内容仍完整保留在本机”，请导出备份并减少内容；减少到一批以内后整体发送一次，意图随确认清除。窗口打开到点击确认之间云端又被其他设备修改时，预览会按最新云端重新生成并要求重新查看。云端在预览之后被其他设备修改时，按既有同步规则三方合并，同一记录冲突仍弹出冲突选择。选择“稍后再说”或关闭窗口，本机与云端都不变，本次会话不再自动提示，下次登录会再次提示。成功后以本机数据指纹和账号记录 `shanhai-migrated-v1:<用户 ID>`，相同的本机数据不再自动提示（升级前按旧格式记录的指纹仍然有效）（本机数据变化后会再次提示）；本机足迹原样保留，退出登录后仍可使用。

**登录期间的限制。** 导入备份仍被禁用（备份整体替换到云端的语义未设计，本机足迹请使用上述迁移）；导出备份仍可用，导出的是当前账号在页面上的足迹（包含未同步修改）。云端缓存存放在 `shanhai-cloud-v2:<用户 ID>`；旧版页面的 `shanhai-cloud-v1:<用户 ID>` 只读，其中未发送的批次连同原请求 ID 在升级时原样接管（改为兼容的旧版操作）并继续重放，旧键原文保留；旧页面之后写入旧键的内容按“旧版页面共存”提示。登录会话在 `shanhai-session-v1`；本地模式的 `shanhai-travel-v2` / `shanhai-travel-v1` 在登录期间不被读写。

**会话与退出。** 账号弹窗（点击头像）显示昵称、同步状态、本机残留的本地足迹提示，以及已登录设备列表，可退出其他设备。“退出登录”需二次确认，会先等待在途写入完成，再撤销本次会话，并清除本账号缓存与会话，随后回到本机的本地足迹；确认文字明确提醒：尚未同步修改会被丢弃，应先导出备份。退出时旧键只在新版已经接管其当时内容（或其中没有未发送内容）时一并清除，旧页面事后写入的未同步内容保留，下次登录提示合并。**注销账号**成功后则清除该账号的全部键（v2 缓存、旧键无论被旧页面改过或已无法读取、接管记录和迁移记录），因为注销已确认丢弃其未同步数据；本机的本地足迹和其他账号的缓存不受影响。撤销请求失败时仍会清除本机状态并提示可在其他设备撤销。使用中的会话过期或被撤销时保留修改并提示先导出、退出后重新登录，不自动清空未同步数据。切换账号时只使用当前账号缓存；其他账号的未同步或无法读取的缓存保留，正常已同步缓存可清理。同一浏览器多个页面修改账号缓存时，收到存储变更的页面暂停编辑与后续同步并要求先导出再刷新；不支持多个标签页同时编辑。

### 账号注销

账号弹窗提供独立“注销账号”入口，显示不可恢复的数据范围，输入“注销”二次确认。密码账号必须重新输入当前密码；OAuth 账号需在最近 15 分钟内重新登录。删除包括当前账号的城市足迹、省份标记、会话、媒体对象、历史快照、同步日志和幂等回执；未同步修改会丢弃，应先导出备份。登录前的本地足迹保留。

服务端先暂停账号，撤销其他会话，再清理 S3 对象，最后删除数据库记录。清理失败暂停编辑并保留重试入口，重新登录也只允许查询账号、退出或重试注销。用户在前端没有收到明确成功结果时不会自动清除账号缓存。成功后清除当前账号缓存和会话；其他账号未同步/损坏缓存保留。

丢失成功响应可用原注销会话在 24 小时内重复确认，返回完成；该回执只保存令牌哈希和过期时间，不保存账号信息或足迹，过期后不可再用，每小时清理过期项。真实 GitHub/Google 授权验收按用户要求留待实际部署后进行。

### 云端备份与历史版本（F3）

登录后，账号弹窗提供“历史版本”入口，打开“云端备份与历史版本”窗口。快照是云端足迹（城市足迹与独立省份标记）在某个版本的完整、不可修改的副本；误删、误导入或被旧数据覆盖后，可以恢复到任一快照。

**何时保存。**

- 迁移前自动保存：云端已有足迹时，确认迁移前先保存（上文“迁移前备份”）。
- 恢复前自动保存：每次恢复都先保存当前版本，因此恢复本身可以撤销。
- 定时保存：服务端每小时检查一次，账号自上次快照后有改动、且最近 24 小时没有任何快照时保存一份；没有足迹或没有改动的账号不保存。
- 手动保存：窗口中的“立即保存快照”。如果当前版本已有快照，不再重复保存，提示“当前内容已有相同的快照”。

快照只包含已同步到云端的内容；窗口在有未同步修改时提示。导入备份在登录期间仍被禁用，所以没有“导入前”快照。

**保留规则（默认值，待产品确认后可调整）。** 快照保留 30 天；无论多旧，始终保留最新的 10 个；同一账号最多 50 个，超出时删除最旧的。快照不可修改，只会被保留规则或注销账号清除。

**恢复。** 列表按时间倒序显示保存时间、来源（手动保存、定时保存、迁移前自动保存、恢复前自动保存）和城市、旅行、省份标记数量。点“预览并恢复”后显示：找回多少条、改回快照内容多少条、移除“快照之后新增”多少条、无需变动多少条（前三项为城市足迹与省份标记合计，“无需变动”按城市、旅行和省份标记逐条计），旅行记录另行说明找回、改回、移除的次数，并说明恢复前会先保存现在的版本。快照里的旅行随城市一起保存与恢复；升级前保存的旧快照（版本 1，每城市一个日期与备注）在预览和恢复时转为版本 2，已存储的内容不被改写。恢复要求云端已确认、没有待发送修改或冲突；只预览不会改变任何数据。

确认后服务端在一个事务内完成：校验预览时的版本仍是云端当前版本，保存“恢复前自动保存”快照，使云端足迹与快照完全一致（包括删除快照之后新增的记录），写入与普通编辑相同的变更日志，因此其他设备通过增量同步跟随。云端在预览之后被其他设备修改时，不恢复任何内容并提示重新选择。请求带唯一 ID，断网后用同一 ID 重试不会重复恢复。恢复成功后窗口显示调整的记录数和“撤销本次恢复”，撤销就是恢复到刚保存的“恢复前自动保存”快照，同样需要预览和确认；撤销也会再保存一份，可以再次反悔。

快照中的旧区域按 F10 已审核映射投影到当前索引；旧载荷不改写，旅行 ID、日期和备注保留。未知区域版本、未映射或迁移后发生碰撞的快照无法预览或恢复，云端保持不变。

## 照片与附件（F4）

登录后，城市足迹编辑窗口有“照片与附件”入口；账号窗口也有入口，可查看全部目的地，包括取消打卡后保留的媒体。选择目的地后可上传 JPEG、PNG、WebP 照片或 PDF 附件，单文件不超过 10 MiB，每座城市最多 20 个（未确认上传也占名额）；每账号每小时最多 60 次签发请求。媒体以区域 ID 关联，不要求该城市仍被标记，不增加城市数量，不改变足迹 revision。

照片最多 2400 万像素、任一边不超过 8000 像素；服务端验证真实格式、完整解码，转为 JPEG（透明背景变白），生成最长边 480 像素的缩略图。原始文件的 EXIF、GPS 与其他元数据不进入可下载照片或缩略图；当前不读取拍摄位置建议，也不按 EXIF 旋转照片。PDF 做文件头与结束标志检查，只下载，不在页面内预览，不做杀毒、内容解析或元数据剥离。HEIC、SVG、其他文件类型暂不支持。

上传先签发 10 分钟有效的私有临时对象地址，浏览器直传，不向对象存储发送登录令牌，再由后端校验并登记。列表显示缩略图、名称、目的地和大小，可鉴权下载。断网或确认响应丢失时，在窗口内“重试上传”复用请求 ID，已经完成的文件不会重复登记；关闭或刷新后未确认上传显示在列表，可确认或删除，但浏览器不会持久化 File，也不会离线排队传文件。超过 24 小时的未确认上传由服务端清理。

删除需二次确认；确认后立即关闭读取，即使对象存储暂不可用也无法通过 API 下载。清理失败可重试，服务端每小时继续清理。缩略图、处理后文件与临时文件一起删除。取消城市打卡默认保留媒体，重新标记同一城市后仍可查看；需要删除时进入媒体窗口独立确认，注销账号会全部删除。城市撤销、足迹迁移和 F3 快照恢复都不影响媒体。

媒体只属于当前账号：他人不可列出、确认、读取或修改，页面不生成公共下载地址；媒体默认不公开：只有在“分享页面”里逐张选择的 JPEG 照片才会进入公开快照（见“公开分享页与预览图（F6）”），也不会加入 PNG 分享图或 JSON 备份、快照，需逐文件下载保存。F5 已在媒体上增加可选的旅行关联（见“同一城市多次旅行（F5）”），仍按城市区域 ID 保留，不随旅行或城市删除。

### F4 验收

1. 登录后在杭州编辑窗口上传 PNG，确认成功后出现 JPEG 缩略图，可下载；桌面和手机无横向溢出。未登录不显示上传入口。
2. SVG、伪装图片、超 10 MiB 或超尺寸照片被拒绝；第 21 个文件（含待确认上传）被拒绝，并发签发也不能越过数量限制。
3. 上传确认响应丢失后重试，列表只有一份文件；重新上传相同的临时 URL 不会覆盖已处理照片。刷新后可对待确认项重新确认或删除。
4. 删除时选择保留，文件仍在；确认删除后本人无法读取，即使 S3 清理失败也无法访问，重试或维护任务完成实际清理。
5. 用户 B 不能读取、确认或列出用户 A 的媒体；B 的删除请求不会影响 A。注销账号删除处理后的文件和缩略图，独立清理队列继续处理晚到的临时上传。
6. 取消杭州打卡后，账号的“照片与附件”仍可看到杭州文件；恢复足迹快照不会删除或恢复媒体，城市数量和同步 revision 不受上传影响。

## 公开分享页与预览图（F6）

登录并且服务端配置了 `share.public_base_url` 后，账号窗口出现“分享页面”。分享是**显式发布的快照**：发布时保存当时的内容，之后新增的足迹、备注和照片不会自动公开，需要再次预览并确认更新。详细规则、部署要求和限制见 [公开分享页与预览图](sharing.md)。

- 可见性：不公开（只保存设置）、知道链接的人可查看（不被搜索引擎收录）、公开页面（允许收录，无目录或发现入口）。首次打开默认选“知道链接的人可查看”，但在确认发布前不会公开任何内容。
- 公开内容：省份地图和统计始终公开；城市名称和颜色、旅行日期、旅行备注、照片各有开关，默认关闭。日期、备注、照片需要同时公开城市名称（关闭城市名称会自动关闭并禁用它们）。
- 照片逐张选择，仅限自己已确认的 JPEG 且所在城市已打卡，最多 12 张；不含 PDF，之后上传的照片不会自动公开。
- 首次发布、新增字段或照片、“用最新足迹更新页面内容”都要先点“预览公开内容”，预览显示将公开的统计、城市、日期和备注，然后“确认发布 / 确认更新”。预览之后足迹或分享设置又变了，服务端不发布任何内容，窗口刷新状态并保留已选项，需重新预览确认。收回字段（取消城市、日期、备注、照片）直接“保存设置”，立即从公开页面移除，不读取新足迹。
- 已发布时显示完整链接、发布时间、“之后有 N 项足迹改动未包含在页面中”和“复制链接”。改为“不公开”会关闭当前链接，再次发布得到新链接。
- “撤销分享”需要二次确认；确认后链接、页面、数据、照片和预览图立即返回“链接不存在或已撤销”。已被他人保存、转发或被平台缓存的内容无法收回。
- 访客打开 `/s/<令牌>` 看到只读页：统计、全国省份地图（固定配色）、省份进度，开启后还有城市、日期、备注和照片。页面不显示账号标识，不提供编辑，不使用访客本机的足迹或登录状态；备注按纯文本显示。预览图（`/s/<令牌>/og.png`）只显示省份层级的统计和地图。
- 令牌无效、未发布、已撤销或账号停用都显示同一页面；`/s/` 下的非法路径也是如此，不会进入个人地图。分享服务暂时不可用时显示“暂时无法打开”和“重试”，不会误报“不存在”。
- 服务端未配置分享时，账号窗口没有“分享页面”，匿名访问 `/s/…` 提示未开启；未配置 `VITE_API_BASE_URL` 的独立本地模式不发送任何请求。

### F6 验收

1. 登录后打开“分享页面”：默认没有任何字段勾选，日期、备注、照片禁用；预览只含省份统计，确认发布后显示 `/s/<43 位令牌>` 链接。无痕窗口打开该链接可见地图与统计，看不到城市、日期和备注。
2. 勾选城市名称、备注、照片并选择一张照片：必须重新预览并“确认更新”；链接不变，访客页面出现城市、备注和这张照片。取消备注后“保存设置”，访客刷新后备注立即消失，且没有读取新足迹。
3. 发布后新增城市：页面不变，提示“之后有 N 项足迹改动未包含”；勾选“用最新足迹更新页面内容”并预览确认后才出现。预览之后另一设备改了足迹：确认时提示没有发布任何内容，需重新预览。
4. 确认保存的响应丢失后重试，只保存一次（相同 mutation ID）；另一设备在你编辑期间保存了设置，则提示变化并刷新。
5. 撤销后：数据、页面、预览图和照片地址都返回同一个 404；再次发布得到新的链接，旧链接仍无效。删除已分享的照片后，页面上该照片消失，其句柄地址返回 404。
6. 用户 A 的分享不能被 B 的会话修改或读取；注销 A 的账号后链接立即失效（即使对象存储清理失败）。
7. 分享页在 320px 与桌面宽度下无横向溢出；键盘可操作分享窗口，Escape 关闭；匿名页没有按钮和输入，不挂载应用，不读取本地存储，请求不带认证头。
8. 服务端 Redis 故障时分享页返回 503 而不是放行；未配置 `share.public_base_url` 时所有 `/s/` 和 `/api/share/` 路径返回 404。

## 共同旅行与好友（F7）

**已实现（#37）：** 好友邀请码、隐私设置、请求/解除与好友足迹对比经 BFF `bff.v1.FriendService`（Cookie + CSRF）；好友码与展示信息保存在 tripmap 业务用户档案，不经 BFF 认证库查询。概览中的共同旅行列表随好友概览只读返回；共同旅行的创建/编辑/媒体等写操作仍走 `tripmap.v1.CollaborationService`（待后续切片迁移）。

登录后，账号窗口出现“好友与共同旅行”入口，城市足迹编辑窗口中每次已同步到云端的旅行卡片也提供“邀请共同旅行 / 共同旅行详情”按钮。

- **好友邀请与双向确认：** 每个账号自动生成唯一好友邀请码（`fc_` 前缀），可通过对方用户名或邀请码发送好友申请。对方接受后双方成为好友；接受前任意一方可拒绝或撤回申请。双方可随时解除好友关系，解除后立即不可再查看对方足迹或对比，未接受的共同旅行邀请一并失效，已加入的共同旅行自动解除协作绑定并将各自的旅行记录保留为独立个人足迹。
- **好友可见范围与足迹对比：** 每位用户独立设置对已确认好友公开的范围：公开打卡城市与颜色（默认开启）、公开旅行日期（默认关闭）、公开旅行记忆/备注（默认关闭；关闭城市公开时自动关闭并禁用日期和备注）。查看好友地图与对比时，始终可对比双方共同探索省份、仅我探索省份、仅对方探索省份；仅当**双方均开启“公开打卡城市”**时，才展示共同打卡城市列表及各自独占打卡城市数量，严格遵守双方各自的公开设置。
- **共同旅行与成员角色：** 创建者（`owner`）可选择自己已同步的某次城市旅行，邀请已确认的好友加入，并指定角色为**共同编辑（`editor`）**或**只读成员（`viewer`）**。受邀好友接受后，服务端自动在其账号内创建或复用该城市的打卡状态（若该成员此前已打卡该城市，保留其原有城市颜色与其他旅行；若未打卡则自动配色点亮该城市），并将该次共同旅行（相同 `trip_id`、日期与备注）同步到其地图中。
- **权限边界：**
  - 创建者（`owner`）与共同编辑（`editor`）可修改该次共同旅行的日期与备注（无论是通过“共同旅行”窗口保存，还是在城市足迹编辑窗口保存并同步），修改会自动同步到所有已加入成员的地图与变更日志中；双方也可为该次共同旅行上传照片并查看所有成员为该次旅行上传的照片（标注上传者）。
  - 只读成员（`viewer`）可在自己地图中看到该次共同旅行并查看详情与照片，但在城市编辑窗口与共同旅行窗口中均处于只读状态，不能修改或删除该次旅行，也不能向该次旅行上传照片（服务端同样拦截只读成员的同步修改与附件上传）。
  - 仅创建者（`owner`）可邀请新成员、切换成员角色（`editor` / `viewer`）、移除成员或解散共同旅行。
- **退出、移除与解散的归属保护：**
  - 成员主动退出共同旅行（或被创建者移除）时，仅从该成员的地图中移除这一次共同旅行子记录（`trip_id`），**保留该成员在该城市的打卡状态、原有颜色、其他个人旅行记录及个人媒体**，且绝不删除创建者或其他成员的记录与照片。
  - 创建者解散共同旅行时，仅解除协作绑定，创建者与所有已加入成员各自地图中的旅行记录与城市足迹均保留为各自的独立个人记录。
  - 共同旅行中的照片始终归上传者本人所有；成员退出、被移除或好友解除后，无权再通过共同旅行接口读取其他成员上传的照片。

### F7 验收

1. 用户 A 通过用户名或邀请码向用户 B 发送好友申请：B 确认前任何一方均不能调用接口读取对方足迹；B 接受后双方在“我的好友”列表中看到彼此。
2. 默认公开设置下（公开城市开启，日期与备注关闭）：A 查看与 B 的足迹对比，能看到共同探索省份、各自独占探索省份及共同打卡城市，但看不到对方未公开的日期与备注；当任一方关闭“公开打卡城市”后，共同打卡城市对比立即隐藏，不会泄露未公开的城市明细。
3. A 将东城区的一次旅行邀请好友 B 作为“共同编辑”加入：B 接受后，双方在各自地图和足迹列表中均看到同一次旅行；B 修改该次旅行的日期和备注后，A 的地图同步更新为最新内容；B 上传照片后双方在共同旅行详情中均能看到该照片及上传者标识。
4. A 将成员切换为“只读成员（`viewer`）”：该成员在城市编辑窗口看到“共同旅行 · 只读成员”标识，日期、备注与删除按钮禁用，服务端拒绝其对该旅行的修改、删除与照片上传。
5. B 在杭州已有一条个人旅行，又接受了 A 的杭州共同旅行邀请（杭州共 2 次旅行）：B 退出该次共同旅行后，A 的杭州共同旅行记录完好保留，B 的杭州城市打卡与原有的个人旅行也完好保留，仅移除退出的那一次共同旅行。
6. A 与 B 解除好友后：双方立即无法再查看对方足迹对比；已加入的共同旅行自动转为各自独立的个人记录，双方足迹均不丢失。
7. 桌面端与手机端（375px 宽度）下，“好友与共同旅行”窗口与城市编辑窗口均无横向溢出，所有表单控件与标签均可通过键盘和屏幕阅读器访问。

## 服务状态页

访问 `/status` 可在不登录的情况下查看云端服务是否可用，桌面与手机尺寸均可读。仅当构建时设置了 `VITE_API_BASE_URL` 才会读取状态；未设置时页面显示“当前为本地模式，没有连接云端服务”，不发任何请求。

- 页面显示总体结论（“全部服务正常”或“部分服务异常”）、各依赖的“正常 / 异常”（数据库、缓存、对象存储）以及分享链接是否开启，并提供“重新检查”按钮。
- 状态来自公网 `bff.v1.StatusService/GetStatus`，由 BFF 经内部 TLS gRPC 向 tripmap 查询，不含任何用户数据。查询不带 Authorization 与 Cookie，不读取登录状态、本机足迹或账号缓存，也不会修改它们。
- 云端服务不可达时显示“暂时无法获取服务状态”并说明本地足迹不受影响，可重新检查；不会显示过期或猜测的状态。

### 服务状态页验收

- 未登录打开 `/status`，在桌面与 390px 宽度下都能完整读到结论与各依赖状态，页面没有横向滚动。
- 某个依赖异常时显示该依赖“异常”和“部分服务异常”；云端不可达时显示不可用说明，点击“重新检查”后恢复显示。
- 打开 `/status` 前后，浏览器本地足迹和已有会话保持不变，状态请求不携带凭据。

## 响应式与键盘交互

桌面采用地图与目的地侧栏布局，手机改为上下布局。手机省内地图工具栏提供“选择城市”入口，打开可滚动选择弹窗：支持名称、拼音、首字母及单字纠错搜索，以及全部、未打卡、已打卡筛选，可连续点选并实时显示打卡数量，也可从已打卡城市进入编辑。弹窗关闭后地图与列表同步更新。手机侧栏城市列表采用单列，保留完整名称，选择行至少 52px、编辑入口至少 44px，不再使用两列内嵌滚动。足迹弹窗在小屏幕内可滚动，导入导出入口保留在页脚。

地图区域可通过键盘聚焦，按 Enter 或空格进入省份或切换城市标记；表单和弹窗沿用原生控件及 shadcn/Radix 的焦点交互。系统偏好减少动画时关闭页面动画和过渡。

## 验收场景

1. 在全国地图点击浙江，显示 11 个城市；点击杭州无需弹窗即标记去过，自动着色，全国浙江也变为已探索。
2. 连续点击同一省的未标记城市，自动分配使用次数最少的颜色，省份数量只增加一次；再次点击城市取消，“撤销”可恢复原颜色、日期和备注。
3. 点击杭州列表旁的铅笔按钮，修改日期、备注或颜色，记录数量不变；刷新后记录仍在，页面回到全国地图。
4. 独立标记某省，然后记录其城市；取消独立标记后城市仍在，省份仍计入已探索。
5. 删除某省最后一条城市足迹：有独立标记时保留该省探索状态，否则恢复未探索。
6. 搜索城市名称能找到所属省份；进入该省后搜索只匹配本省区域，无匹配时有提示。

### F3 快照验收

1. （配置后端）云端有 3 条城市足迹（各 1 次旅行）和 1 个省份标记：点“立即保存快照”，列表出现“手动保存 · 3 个城市足迹、3 次旅行、1 个省份标记”；再点一次提示已有相同快照，列表不增加。

## 区域数据与兼容（F10）

登录后，账号窗口的“区域数据与兼容”显示本页区域版本，按版本读取服务端索引并预览自己的旧区域。前后端必须使用同一版本；不一致时暂停同步、保留缓存，提示刷新页面或升级服务端，不在线替换地图。

- 本地缓存、账号缓存和备份读取时，只按明确登记的历史 `(ID, 名称, 省份)` 映射规范化。v1 的旅行 ID 仍以原区域 ID 生成；已有旅行 ID、日期、备注、颜色及独立省份标记不变。仅打开本地页面不写入；首次版本化保存前保留原文，保存副本失败则不覆盖。
- 云端迁移只预览不修改；确认要求没有未同步修改、冲突或缓存异常。服务端锁定自己的账号，复核预览 revision、保存迁移前历史版本，再在一个事务内更新区域字段、旅行和媒体的区域引用，并写入同步日志。媒体文件、稳定旅行 ID和已发布分享不变；取消打卡后保留的媒体也可迁移。
- 断网或丢失响应后用同一请求 ID 重试，不重复迁移。预览后云端变动则整批拒绝，重新预览；未知区域或目标 ID 碰撞则整批停止，不猜测、不合并、不丢弃记录。
- 当前登记的真实变化只有金门、马祖从台湾归入福建，两者旧 ID 保持不变。其他省份与全国统计口径不变：34 省、497 个可记录区域、391 个全国统计目的地。

**当前限制。** 区域更新需维护者审核并部署静态索引及迁移表，不抓取实时行政数据。仅支持明确的一对一城市/区县映射；省份 ID 改号、拆分、多对一记录合并以及共同旅行跨账号 ID 改号没有自动协调方案，遇到后者停止迁移。未来有真实 ID 改号时，必须先迁移云端再编辑；旧 ID 待发送批次无法安全继续时原请求和缓存保留，需先导出并由维护者处理，不自动丢弃或改写队列。区域迁移没有独立撤销入口；历史版本仍按当前映射读取，不回退当前行政区划。

### F10 验收

1. 桌面和手机打开区域窗口：显示版本、金门/马祖旧归属与新归属；关闭或仅预览不改数据、不新增快照，手机无横向溢出。
2. 确认迁移后，福建归属持久化；原旅行 ID、日期、备注、颜色、独立台湾标记及媒体保留，其他账号不变；其他设备经增量同步跟随。
3. 迁移成功但响应丢失：重试使用同一 mutation ID，只保存一份迁移前版本、只执行一次。云端在预览后改变时整批拒绝，没有部分迁移或额外快照。
4. 当前记录无需迁移时按钮禁用；未映射、碰撞、共同旅行 ID 改号时显示阻止项，禁止部分迁移。
5. 旧 v1/v2 缓存、备份和快照按登记映射读取；模拟已退休 ID 时旧 `legacy-<原 ID>` 和现有旅行 ID 保留，快照原始载荷不改写。模拟未知区域版本时原文保留、不自动恢复部分数据或发送批次。
6. 首次保存旧缓存先保存原文；副本写入失败时原键不变。F0 已明确保留/导出原文的恢复流程不要求重复占用存储；退出或注销只清理当前账号的区域原文副本，不清理本地或其他账号副本。
7. 前后端区域版本不同：清楚提示升级，同步和迁移暂停，离线目标与原请求保留。

## 行程与路线连线（F11）

页面“行程路线”按钮打开行程窗口，把至少 2 个、至多 100 个城市/区县站点按顺序连成一条行程，并在全国与省内地图绘制路线。未登录时行程保存在本机（键 `shanhai-itineraries-v1`）；登录后保存在账号并在本机缓存一份（`shanhai-cloud-itineraries-v1:<用户 ID>`），重新打开页面立即恢复，联网后以云端为准。

- 每条行程有名称（≤80）、备注（≤1000）、路线颜色（与足迹同一五色）和有序站点；每站可填城市、日期（可空，须为真实日历日期）、备注（≤200）、关联旅行 ID（可选）和到达该站的交通方式（高铁/铁路、自驾、飞机、轮渡、其他）。站点可上移、下移、移除；同一城市可重复出现。
- **路程与时间估算（当前已实现）：** 供应方为内置的 `offline_great_circle`，按随项目分发的城市中心点计算球面直线距离，再按交通方式的绕行系数和平均速度（含固定缓冲）估算路程与用时；不发起第三方地图请求、不需要 API Key，费用为零（`free_builtin`）。结果仅供参考，不是实时导航。窗口会明示供应方、费用与缓存规则；前后端用同一整数运算，结果一致。
- 地图：全国 SVG 与 OSM 底图用虚线连接所有站点并按序号标注；省内地图只画两端都在该省内的路段与该省内的站点。地图上显示当前路线条，可“编辑行程”或“隐藏路线”，选择会随页面恢复。
- 登录后每次保存携带版本与唯一请求 ID：另一设备已改动同一行程时拒绝覆盖；断网或丢失响应后重试同一内容只生效一次。行程隶属于账号，其他账号不可读写；退出登录清理账号缓存，注销账号一并删除行程。配置后端时，云端行程经同源 `bff.v1.ItineraryService`（Cookie 会话，写操作带 CSRF），不再走 `tripmap.v1` 公网 Connect。
- 备份：导出文件在有行程时附带 `itineraries` 与 `activeItineraryId`，导入时校验并一并替换；没有该字段的旧备份仍可读且不改动现有行程。
- F10 区域迁移同样处理行程站点里的历史城市 ID；行程里出现未登记的区域时作为阻止项停止整批迁移，不猜测、不改写。

**当前限制。** 不提供实时路况、票价、班次或步行/骑行方案；估算按直线距离加系数，山区或绕行路线可能偏差很大；单个城市使用区县中心点作为站点位置（直辖市、特别行政区按区县）。没有行程分享、共同编辑或日期冲突检查；行程不进入 F8 统计，也不改变足迹数据。

### F11 验收

1. 桌面与手机：创建 3 站行程，窗口实时显示每段路程/用时与总计；少于 2 站或日期无效时给出错误并不保存。
2. 保存并展示：全国地图出现路线与序号标记；进入站点所在省份只显示该省站点；手机宽度无横向溢出，路线条可点击“编辑行程”“隐藏路线”。
3. 调整顺序后保存，路段与总计按新顺序重算；刷新页面后行程和展示状态恢复；删除后刷新不再出现。
4. 云端：保存响应丢失后重试只产生一个版本；保存失败时窗口保留错误且云端不变；刷新后恢复账号行程；另一个账号看不到。
5. 估算供应方、费用与缓存规则在窗口内可见，运行时没有第三方地图请求。

## 提醒与通知（F12）

登录后，账号弹窗里的“提醒与通知”按钮打开设置窗口。**所有提醒默认关闭**；每一类提醒、每个渠道都可单独开关，需要服务端配置邮件（SMTP）或浏览器推送（VAPID）后对应渠道才可用，未配置时窗口明示“服务器未配置”并禁用开关。未登录的本地模式没有提醒。

- **提醒类型。** 回忆提醒（`memory`，“一年前的今天”）：用户所在时区的今天，若往年同月同日有旅行日期，则发送一条提醒；2 月 29 日的旅行在非闰年于 2 月 28 日提醒。年度旅行回顾（`annual_report`）：每年 1 月 1–7 日（用户本地日期）提醒查看上一年的回顾，只包含数量，且上一年没有旅行时不发送。旅行日期取自账号现有旅行（旧版本 1 账号读取城市足迹的日期）；没有日期的旅行不会触发回忆提醒。
- **时间。** 窗口里设置时区（默认 Asia/Shanghai）和“当天几点后发送”（0–23 点）。服务端每小时检查一次，到达本地发送小时后才发送当天提醒；同一用户、类型、渠道、本地日期（年度为年份）至多发送一次，重复检查或多实例同时运行不会重复发送。发送失败最多尝试 3 次，进程在发送中途崩溃时宁可漏发也不重复。
- **内容与隐私。** 通知永远不含备注和照片。默认只写“你有 N 段旅行记忆”，不出现地点；仅当用户勾选“在通知中显示城市名称”时才写城市名（窗口内有实时预览）。邮件地址只用于发送用户开启的提醒；设置接口只返回打码后的地址，推送端点不返回给客户端。
- **邮件渠道。** 先输入邮箱，系统发送 6 位验证码（15 分钟内有效，最多输错 5 次，同一账号和同一地址都有每小时发送次数限制），验证通过后才能开启邮件提醒；未验证的地址不会收到提醒。“发送测试邮件”发送固定的通用内容。“移除邮箱”会忘记地址并关闭所有邮件提醒，其他设置保留。
- **退订。** 每封提醒邮件的页脚和 `List-Unsubscribe` 头带签名退订链接（支持邮件客户端一键退订）。链接打开后只显示确认页，点击确认才退订；退订只关闭链接对应的邮件类型（页脚提供“全部提醒邮件”），已退订后不再发送，之后需要在设置窗口重新开启。退订页不被搜索引擎索引、不缓存、不在访问日志记录令牌。
- **浏览器推送。** “在此设备启用推送”会注册 Service Worker（`/sw.js`）、请求通知权限并把订阅保存到账号；可停用此设备、发送测试推送。需要 HTTPS（本机 localhost 除外），不支持、被拒绝或不安全访问时窗口说明原因。同一浏览器登录另一个账号时，订阅会转移到新账号；退出登录时此设备会自动取消订阅，不再收到该账号的推送。每个账号最多 10 台设备；推送服务返回订阅失效（404/410）或连续失败 5 次的订阅会被清除。点击通知只会打开本站，不会跳到其他网站。
- **关闭后不再发送。** 关闭某一开关、移除邮箱、退订或注销账号后，之后的检查不再发送对应提醒；注销账号级联删除全部通知设置、订阅和发送记录。
- **与 F8 的关系。** 年度旅行回顾提醒只发数量；完整年度报告仍在应用内查看（见“足迹统计、年度报告与成就（F8）”）。

**当前限制。** 没有站内收件箱或消息中心，提醒只通过邮件和浏览器推送送达；不支持短信、App 推送或自定义提醒时间表；回忆提醒每天最多每个渠道一条，不逐条列出多个旅行；每小时检查一次，所以实际发送可能比设定小时晚最多约 1 小时（服务停机而错过的日子不补发；当天发送小时之后恢复服务，仍会发送当天的提醒，年度提醒在 1 月 1–7 日窗口内同理）；邮件需要运营方自备 SMTP 服务，推送依赖浏览器厂商的推送服务，本仓库测试使用本地假 SMTP 与假推送服务，未经真实邮件服务商和真实浏览器推送服务验证；投递语义是最多一次，没有送达回执或统计。

### F12 验收

1. 全新账号打开设置窗口：所有开关均未勾选；服务器未配置邮件或推送时，对应开关禁用并说明原因；手机宽度无横向溢出。
2. 验证邮箱：错误验证码被拒绝；正确验证码后显示打码邮箱并可开启邮件提醒；修改时区、发送小时、“显示城市名称”后保存，关闭窗口重新打开仍为保存的值，预览在勾选前不含城市名。
3. 回忆提醒：存在往年同月同日的旅行时，在用户时区的发送小时之后收到一次提醒；没有旅行的日子、发送小时之前、关闭开关后都不发送；换到另一时区后按新的本地日期判断；同一天重复检查不重复发送。
4. 隐私：提醒和测试消息不含备注、照片；默认不含地点；勾选后只含城市名。
5. 退订：打开退订链接只显示确认页、不改变设置；确认（或邮件客户端一键退订）后同类邮件不再发送，其他类型保持；伪造或被篡改的令牌无效。
6. 推送：启用此设备后账号显示 1 台设备，测试推送可达；停用或退出登录后该设备被移除；拒绝权限时显示说明且不登记订阅。
7. 移除邮箱后邮件提醒全部关闭但其他设置保留；注销账号后通知相关数据全部删除。

## 当前功能边界

未登录时足迹记录是浏览器本地模式；配置后端后可选登录，足迹保存到云端并在页面可见时同步（见上文“账号与云端同步”）。前端不依赖后端即可完整使用（未配置 `VITE_API_BASE_URL` 时不发送任何后端请求）；后端基础设施见 [后端初始化](backend.md)。云端有历史快照与恢复（见上文“云端备份与历史版本”），但迁移本身没有单独的撤销入口，需要通过迁移前自动保存的快照恢复；快照保留期限是默认值，尚未经产品确认；快照不能手动删除，也不能下载为备份文件。有可选的公开分享页（见“公开分享页与预览图（F6）”，需要服务端配置）、好友足迹对比与共同旅行协作（见“共同旅行与好友（F7）”）以及按用户时区生成的年度报告与旅行成就（见“足迹统计、年度报告与成就（F8）”）。有行程与路线连线（见“行程与路线连线（F11）”，路程与用时为离线估算）。可选的回忆提醒与通知（见“提醒与通知（F12）”，默认关闭，需要服务端配置邮件或推送）。尚无找回密码。地图边界不是实时更新；OSM 底图是可选的联网功能，离线时不可用，具体数据年份与维护限制见地图说明。

### F1 补齐验收

- 两台设备交错编辑不同城市，批量提交与增量拉取后均保留；同一记录冲突仍由用户选择。
- 批量提交已在服务端生效但响应丢失：刷新后原请求 ID/内容恢复，重放不覆盖更新后的记录；在等待期间发生的新本机编辑也保留。
- 老账号 revision 不为 0 但没有新日志时，自动回退完整快照；旧逐条写入仍兼容，并进入新日志。
- 注销确认未输入或密码错误时不删除；S3 清理失败可重试；注销完成后全部会话失效，其他用户记录不受影响，登录前本地记录仍在。
